# 综合评审约定

## 输入与顺序

候选为 /tmp/arena-sayhear-roadmap/candidate-{1,2,3,4}/plan.md。全部完成后才能开始交叉评分。主 Agent 完整读取四份候选，独立逐项评分后与跨模型评审对照。

## 评分

每项 0 至 5 分，满分 30。缺乏来源的重大技术断言不能得到证据项高分。提前固定 schema、擅改年底目标或产品定位须单列问题，不能被总分掩盖。

1. 与 CONTEXT 产品愿景、数据边界和年底范围一致。
2. 技术与产品调研覆盖典型路线，结论有一手证据并承认未知。
3. 技术路线便于理解、可替换、可维护，避免提前引入复杂度。
4. 阶段依赖合理，验收能观察到真实行为。
5. 学习活动融入真实产品，每周约 10 小时预算可信。
6. 区分已定共识、研究推荐、待用户决定与待实测事项。

## 输出

选定一份可继续维护的基底，解释评分。每个未选候选最多提取一至两个有效改进，若路线本就收敛则记录共识。不平均拼接相互冲突的路线。

交叉评审与最终审计分别报告事实错误、需求遗漏、证据不足、学习和排期风险。研究推荐不能写成 Luke 已接受的决定。审计只读，不改计划，也不创建外部 Issue。
