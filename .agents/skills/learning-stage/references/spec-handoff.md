# SPEC 交接

## 就绪检查与汇总

检查体验行为、范围与非目标、关键决定、失败和边界场景及验收方式。测试边界在讨论时确认，已有确认直接复用。影响实现的缺口返回对应环节；非阻塞未知注明预期、验证方式、失败处理。理解回访单列，不充作产品验收。

读取并复用 `to-spec`，输入计划、接续记录、共识、ADR、证据与验收讨论，使用其模板，以中文和项目术语综合，不重做访谈。故事覆盖已确认行为与边界，不扩范围；决定描述职责与契约，不固化易过期路径。承载精确决定的原型片段按该 skill 规则保留并注明来源。

按阶段适用性补足：

- 正常、取消、停止、超时、失败、重复请求的已定行为与用户可见结果。
- 数据归属、来源、读写边界、接口与事件契约；未定内容及影响。
- 数据隔离、Provider 内容发送、访问与隐私要求。
- 验收场景的前提、动作、预期、证据，覆盖真实行为、体验、运行可观察性。
- 测试边界、现有先例、真实 Provider、部署或人工验证缺口及环境。静态检查不代表线上验证。
- 依赖、实施顺序、构建前置、非目标、非阻塞未知、重评条件。

逐项核对构建、开发、体验决定的 ADR 与索引，SPEC 链接依据；SPEC 和学习笔记均不替代 ADR。未定细节不编造，未验证不写结果；阻塞决定未解时保留草稿，不标 `ready-for-agent`。

## 发布与接续

读 `docs/agents/issue-tracker.md` 和 `docs/agents/triage-labels.md`。完整 SPEC 以 GitHub Issue 为权威，本地仅索引与链接。核对现有 working spec 状态，保留他人改动。

按当前授权发布。明确调用 `to-spec` 发布或已有 Issue 写入授权则直接沿用；仅调用本 skill 不扩大授权。缺授权时先完成可审阅的任务专属临时草稿，再请求发布授权；接续文件登记路径、待发布状态及临时文件清理风险，恢复时核对。未发布不宣称完整交接完成。

发布前核对仓库、重复 Issue、账号；默认 `luke-agents`，其他账号须 Luke 明确授权。更新已有 SPEC 也须对应授权，不因重复擅自覆盖。就绪后按 `to-spec` 标 `ready-for-agent`，不由此推定构建、提交、推送、部署授权。

发布后读回正文与标签，核对验收和决定。接续文件保存 Issue、ADR、证据入口、待验证项、理解回访及构建第一步。草稿或失败如实报告状态。

## 归类、合入与下一阶段

SPEC 就绪后盘点本阶段产物，按阶段与功能整理：`docs/plans/stages/stage-N/features/<feature>/` 保存接续、研究、决策简报和证据，`.audit/stages/stage-N/features/<feature>/` 保存本阶段可追溯审计及验证记录。子目录按需创建；跨阶段路线图留在全局入口。ADR 保持 `docs/adr/`，学习笔记留外部目录，完整 SPEC 留 Issue；各目录维护简短索引与链接，避免重复正文。

仅迁移本阶段自有文件，保留原始证据和时间，不夹带他人改动、不删除记录或收录密钥、私人内容、原始敏感日志及纯临时输出。迁移后更新仓库引用、脚本路径、接续记录和已发布 Issue 链接，检查相对链接及路径消费者，保证新会话可定位；SPEC 引用的证据须在合入后可访问，未提交本地路径不算已交付。无法安全迁移的并行文件先登记待整理，不能误报完成。

阶段交付包含 commit、推送、PR 和合入 main，按当前有效授权执行，已授权不重复询问；仅修改本 skill 不触发某个产品阶段的交付。先查 Git 状态及 staged/unstaged diff，只暂存本阶段相关内容。使用 Conventional Commit，说明行为变化、原因与验证。调用 `pr` 编写 PR 正文，目标为 main，默认使用 `luke-agents`；复用仓库审查与合入流程，不绕过保护。检查范围、引用、所需验证、独立审查和 CI，处理有效反馈后合入；受阻时记录原因和下一步，不把 PR 已创建当已合入。

读回 GitHub merged 状态、合入 SHA 和更新后的 `origin/main`，核对 SPEC 指针、ADR、归类文档确实在 main。接续记录在合入前写入文档 PR 与下一步，合入结果由 PR/Issue 回执承载，避免为记录自身合入 SHA 无限追加提交。交接报告给出 SPEC、目录索引、PR、合入 SHA、剩余验证及学习回访。main 基线一律指 fetch 后核实的 `origin/main`，不能用含未发布提交的本地 main 替代。后续构建与新阶段从该基线新建分支，不续用讨论分支；脏工作区先保留，不强制切分支、重置、删除分支或 worktree；能安全继续则继续，否则使用已获授权的独立工作区，缺授权时记录阻塞与所需动作。
