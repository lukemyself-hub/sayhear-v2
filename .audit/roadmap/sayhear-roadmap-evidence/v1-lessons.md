## 1. 有证据的旧教训

### 1.1 产品边界与人格

1. **温暖与立场必须同时成立，反谄媚是产品能力而不是温暖的代价。** Pi 的 “safety over agreeableness”、Nomi Aurora 的 “supportive doesn't mean blindly agreeing”、Tolan 的向外好奇都指向同一结论（A:418–435、B:143、B:245–247）。V2 已把“事实诚实、不盲目附和”写进人格（V2:17）。强度：强。

2. **非人身份是谦逊与边界的装置，不是需要隐藏的缺陷。** Tolan 用外星人设定解释知识缺陷并回避恋爱框架，Pi 坚持不冒充人类（A:424–429、B:208–211）。V2 明确“非人类 AI、不虚构人类身份或离线经历”（V2:17）。强度：强。

3. **不要出售关系，也不要把记忆或关系深度做成付费轴。** Replika 的付费关系状态、Kindroid 的付费记忆层、Character.AI 的付费 Facts 都被反复记录（A:541–546、A:547–552、B:261、B:268、C:54–56、C:557–559）。V2 没有商业化计划，但“不经营浪漫、排他或依赖关系”已是边界（V2:17）。强度：强。

4. **关系边界一旦建立就不要反复。** Replika 2023 年移除 ERP 后的用户伤害，以及 HBS 工作论文对“AI 身份不连续引发哀伤”的度量，是这条教训最完整的证据（A:547–552、B:98–99）。v2 本身是一次重建，这条同样适用于“重建时如何对待旧用户与旧数据”。强度：强。

5. **用户自述不等于经核验的事实，AI 推断不能冒充用户原话。** 这是 A、C、D 三份研究共同指出的行业空白，也是 V2 的明确要求（A:17–20、C:30–33、V2:58）。没有公开产品做到 Evidence 级区分，所以这是差异化方向，不是照抄对象。强度：强，但实现无先例。

6. **危机处理要产品化，不能停在帮助中心免责。** Pi 的危机协议、Nomi 的 Odyssey 事故与 Aurora 修复、Character.AI 的 U18 退出，构成行业收敛方向：识别、出示现实资源、不按常规陪伴继续（A:25–27、A:492–497、B:319–330）。V2 目前没有写危机处理或年龄边界，这是缺口，不是已解决项。强度：强。

7. **年龄边界是未决产品决策。** A 和 B 都把“SayHear 文档未定义年龄边界”列为缺口（A:672–674、B:325）。v2 仍未定义。不要把它当作 v1 已经解决的问题带过来。

### 1.2 记忆与连续性

8. **记忆是检索系统，不是 transcript；每轮从零重建上下文。** Tolan 的公开案例是这条最直接的来源：“cached prompts just didn't cut it”“Build memory as a retrieval system, not a transcript”，每轮用近期摘要、persona、向量召回、语气信号重建（A:134–139、A:469–475、B:231–238、D:494–495）。强度：中，单一厂商案例，但被四份文档反复引用并与多家分层召回收敛。

9. **canonical 数据必须归产品自己，派生索引必须可重建。** N 的退出成本论证、D 对 Tolan “向量只是检索层”的核对、V2 对 canonical 数据结构的要求，三点同向（N:416–418、N:428、D:24–30、D:225–237、V2:26）。强度：强。

10. **离散、版本化、显式 supersede 优于原地重写。** DynamicMem 发现 consolidation/merge 型设计在“偏好已改变”场景最多掉 50 分，append-only 更能保留新旧值；LangChain 官方文档也说 collection 比整体重写 profile 的下游 recall 更高（D:219–223、D:400–411、D:475–480）。V2 要求区分“用户明确表达”“AI 观察与推断”“随时间更新的画像”（V2:58），与这条同向。强度：强。

11. **检索是主要失败源，混合检索与 precision-first 比记忆架构本身更重要。** DynamicMem 中超过 93% 的失败来自检索而非回答模型；MemoryAgentBench 中朴素 BM25 在精确检索上强于多数 agentic memory；LoCoMo 的 adversarial 类显示上下文越长越容易“无据而答”（D:254–256、D:297–300、D:400–411）。强度：强。

12. **预算化、策展过的注入优于 top-k 倾倒。** N 估算 Mem0 每次查询注入约 7k token、Zep 2.7–5.8k，按每月 300 回合计算，注入 token 是比记忆服务账单更大的静默成本；D 也记录生产系统实际注入面在 1–4K token 量级（N:378–384、D:282–292）。强度：中，数字多为估算或厂商配置。

13. **抽取节奏的行业共识是“会话内轻量抽取 + 会话后或夜间异步整合”。** mem0 的 per-message-pair、OpenAI Cookbook 的 live 蒸馏加 session 末整合、Letta 的 sleep-time、Tolan 的夜间压缩，都落在同一区间（D:90–109、D:554–564）。强度：强，多个独立来源收敛。

14. **不要静默删除或静默改写记忆。** ChatGPT 的自动 update/combine/remove、Tolan 夜间压缩的删除侧、Replika 的不可见深层记忆，都被列为反面模式（B:350、C:436–445、C:538–541、D:218–223）。V2 要求用户能查看、纠正、遗忘、导出、删除（V2:19）。强度：强。

15. **召回应当无仪式地织入回复，归因按需给出。** 九家产品没有一家做“我想起来了”式技术预告；最接近的 Claude 也只是 citation 指回原对话（C:19–23、C:407–415、A:510–515）。V2 的产品愿景是“当下感到被听懂，之后感到被记住”（V2:15），与无仪式召回一致。强度：强。

16. **“记忆可见、可纠正”是行业趋势，但没有一家达到逐条 Evidence 级解释。** ChatGPT 的 Sources 明确“不穷尽”，Claude 的 citation 只到对话粒度，Kindroid 的图标只说“用了”不说“用了哪条”（C:24–29、C:417–423、D:24–30）。强度：强，属于有充分覆盖的负向发现。

17. **删除与派生视图的一致性普遍是弱点。** ChatGPT 删对话不等于删记忆，Gemini 删除有延迟且双源要两边删，Replika 删除会损害回忆能力（C:36–38、C:425–434）。V2 要求“内容查看与清理”，且测试库不得连接或重置用户库（V2:53–56）。强度：强。

18. **记忆质量要用产品内盲评、小失败集和内容无关遥测来评，不用排行榜选型。** Tolan 的行为研究员日志审阅、10–200 条小数据集、人工并排判断；Character.AI 的维度化 LLM-judge 两步评分；Claude 的记忆安全维度清单（A:519–532、C:449–463、D:427–442）。强度：强，多来源收敛。

19. **基准分数不能用来选冠军。** LoCoMo 答案键被独立审计发现约 6.4% 错误，诚实上限约 93.6；厂商互测仅配置差异就值约 9 分；同条件复测会把梯队压平（N:319–336、D:413–425）。强度：强，含独立审计。

20. **短历史下 full-context 仍然最强，长历史下记忆系统才反超。** mem0 论文与 DMR 在短历史下 full-context 精度更高；LongMemEval 的 115K 长历史下记忆系统才显示优势（D:524–529）。这条是对“v2 一开始就上复杂记忆架构”的直接反证。强度：强。

### 1.3 Harness 与工程

21. **买运行时、自有 canonical 与产品语义、把记忆藏在窄接口后面。** N 的推荐拆分是 Mastra 做运行时，自己的 Postgres 存 messages/episodes/bio/open-loops/journals，记忆插件只做索引与召回，Reflection 用自己的 cron（N:31–47、N:422–458）。强度：中，论证加一手经验，且 N 自己要求用实验定案。

22. **七个必须自有的接口。** MessageStore、EpisodeWriter/Reader、UserModelStore、OpenLoopStore、MemoryIndex、ReflectionJobs、ContextAssembler（N:460–481）。其中 ContextAssembler 与“每轮重建上下文”是同一件事。强度：中，属于设计建议而非实证结论。

23. **插件不能成为某个产品概念的唯一住所。** 如果插件的模型只有 `fact(user_id, text, embedding)`，episodes、open loops、reflections 只能被编码成事实，状态、来源、顺序、到期感全丢（N:394–396）。这是 N 证据最硬的风险之一。强度：中偏强。

24. **框架 churn 的真实成本是“按厂商时间表被迫迁移”。** AutoGen、Semantic Kernel、LangChain AgentExecutor、Zep 社区版、Letta heartbeat、Mem0 图记忆移出 OSS 都是例子；对策是 MIT/Apache、可 vendor、窄接口、选“这一层就是它主业”的厂商（N:386–392）。例子有时效性，纪律本身可迁移。强度：强。

25. **多用户隔离、跨用户召回、记忆注入、删除实测必须在设计时就处理。** namespace 按 user 而不是 thread 建 key、resource ID 撞车、记忆作为持久化 prompt 注入面、删除要覆盖备份与索引（N:406–414）。V2 要求初期数据归属与访问设计兼容未来多用户（V2:30、V2:53–56）。强度：强。

26. **可检查性是用户能感知的质量。** OpenClaw 的 Markdown 记忆可看、可改、可 git diff；N 的判断是“记错的东西会被修掉，而不是复利式累积”（N:95、N:404）。V2 要求“可展开的运行详情”（V2:28）。强度：中。

27. **压缩前先 flush 耐久事实。** 上下文压缩丢弃内容之前，把耐久事实写回记忆文件（N:89）。这与 D 的“摘要只作上下文压缩、不作事实真源”同向（D:184–193）。强度：中，OpenClaw 设计实践。

28. **当天洞察用“今天 + 昨天原始笔记”补偿，耐久层由反思治理。** OpenClaw 的 dreaming 晋升节奏（N:91）。这是 v2 “跨日连续性”的一个候选实现，不是已验证结论。强度：弱到中。

29. **后台整合不能阻塞读取路径。** LangMem 后台批处理式 search p50 17.99s、p95 59.82s，被 mem0 作者标为交互场景不可用；Zep 的新记忆曾“数小时后才可检索”（D:116–118、D:536–539）。V2 把 v1 的时延问题列为重建动因之一（V2:9）。强度：强。

30. **重建或人格变更不能破坏连续性，必须版本化、可回放。** Replika 2.0 的记忆清空报告、Nomi/Kindroid 的旧模型保留选项、Replika 回退到旧版本，都把陪伴行为变更当成变更管理问题（A:559–563、B:254、B:262）。v2 是受控重建，这条直接适用于旧数据迁移与人格切换。强度：中偏强。

31. **导出与删除从第一天成立。** N 的退出成本论证、C 的“记忆可携带作为信任面”、V2 的导出与删除要求（N:418、C:496–498、V2:19、V2:56）。强度：强。

### 1.4 学习与决策方法

32. **先写决策规则，再跑实验，不许事后改。** N 的两周实验在开工前定死“买入栈盲评高 ≥0.5 分，或质量打平但搭建/维护工时少 ≥40% 则采用买入路线”（N:563–567）。方法可复用，阈值是 v1 语境。强度：中。

33. **14 天合成语料是一个可直接复用的测试数据集模式。** 埋一组事实、第 9 天埋矛盾（换工作）、第 3 天埋 open loop（等活检结果）、加人物关系网与情绪弧线、第 14 天导出日记与 bio（N:529–531）。这与 V2 要求的“高度仿真、信息充足、关系清晰、可版本化、可重复装载”的测试库高度契合（V2:53–55）。强度：中，设计合理但未验证。

34. **负向发现必须标注为负向发现。** A 的 §8、N 的 §11 都明确说“查无”不等于“不存在”（A:668–683、N:569–583）。这是四份文档共同的方法纪律。强度：强，属于证据规范。

35. **厂商自报、供应商案例、单人一手经验要分级标注。** A、B、D 都有证据等级表；N 用“厂商自述 / 独立证据 / 一手经验 / 估算”四类（A:33–50、B:26–34、D:72–85、N:26–30）。强度：强，属于证据规范。

## 3. 冲突

### 3.1 跨文档事实冲突

1. **Pi 是否有逐条记忆管理界面。** A 说设置页 `Settings > Account > Manage Memories` 可增删改记忆条目（A:88–90）。B 说“长期记忆无独立编辑界面，第一方文档未提供任何 memory editor”（B:60）。两处引用的都是 Pi 的记忆帮助页。这是直接事实冲突，使用前必须回查第一方页面。倾向 A 更具体，但未复核。

2. **Nomi Mind Map 是否支持删除。** A 说可查看 dossier、编辑纠错、新增、设优先级、删除（Low priority）（A:303–304）。B 说用户可查看、编辑、新增，“官方未提删除”（B:155）。直接冲突，影响“用户控制面完整度”的判断。

3. **LoCoMo 与 Zep 的分数口径。** N 的图表写 Zep 94.7、Mem0 Platform 92.5，并说 Zep 的 94.7 已高于数据质量上限（N:330–334）。D 记录 mem0 论文给 Zep 65.99、Zep 自报修正后 75.14、第三方复测约 58.44，mem0 论文自报 66.88/68.44（D:413–425）。这些数字不是同一产品、同一配置、同一切片，不能混用。N 自己也说 Mem0 OSS 不等于 Platform（N:309）。结论一致，数字冲突。

4. **Tolan 的年龄定位。** A 记录 App Store 12+（A:157）。B 说产品为 teen+adult，未设硬性年龄线，建议家长参与（B:226）。12+ 商店分级与“teen+adult、无硬线”不是同一层面的陈述，但并列时容易误读。

5. **Pi 的年龄定位。** A 记录官方危机页 18+，但 Apple 17+、Google Play “Teen”（A:672）。B 只写官方 18+（B:67）。这不是文档间冲突，而是第一方来源之间的冲突，A 记录得更完整。

6. **Character.AI U18 退出的时间。** A 写 2025-10 宣布并执行（A:250）。B 写不晚于 2025-11-25 生效，过渡期先限每天 2 小时（B:129）。B 更精确，A 是概括。

7. **Replika 2.0 记忆清空。** A 明确说只有第三方用户报告、公司未承认，不作为事实引用（A:559–563、A:674）。B 完全没有提 2.0。不是冲突，是覆盖不对称。使用时只能按“未经第一方确认的报告”处理。

8. **Nomi 主动消息的细节。** A 写四档频率、zero scripts（A:279–285）。B 增加了指数退避、22:00–8:00 静默、通知不含正文、免费用户额度用尽仍收消息（B:150）。B 是 A 的超集，不是冲突。

### 3.2 结论层冲突

9. **“现有 seam 不需要改”与“换掉编排与记忆管道”。** A 的 W9 结论是现有 PostgreSQL、Context Compiler、慢速 workflow 的形态已被 Tolan 验证，“不需要为温暖、好奇、连续性目标改架构”（A:469–475、A:665–666）。D 的 §10.6 也说没有证据要求改变已定产品法或架构边界，所有映射都在参数层（D:665–670）。N 的结论是复用方向成立，换掉的是编排与记忆管道，不是产品语义（N:37、N:47）。这三者不是同一层：A/D 说的是记忆语义与 seam 形状，N 说的是谁写管道、谁拥有存储。引用时必须写清层级，否则会互相误读。

10. **OpenClaw 的 heartbeat 主动性与“不做对话外主动消息”。** N 把 heartbeat 列为值得偷的五件设计之一（N:93）。A 的 A5、B 的 §10.3、C 的 §14.3.9 都把对话外主动消息判为与 v1 边界冲突，且是依赖回路的一部分（A:565–570、B:263、C:560–561）。V2 把 Open Loop 与适时跟进列为长期方向（V2:19），但没有决定是否允许对话外消息。这是 v2 必须显式裁决的开放冲突，不能默认照搬任何一边。

11. **文件式记忆与 Postgres canonical。** N 说 files-as-memory 是唯一让 Open Loop 天然成为一等公民的方案，因为 schema 是你的（N:296、N:305）。A 与 D 的形态是 PostgreSQL 权威加 pgvector 可重建索引（A:607–618、D:225–237）。两者的共同不变量是“canonical 归你、派生可重建”，冲突只在存储形式。v2 不应把“文件”或“Postgres”当成结论，只应把不变量当成要求。

12. **用户能否直接编辑记忆。** C 把 Kindroid Learned Context、Character.AI Facts、Nomi Mind Map 的编辑、Replika 手动添加列为与 v1 ADR-0001/ADR-0057 冲突，不采纳（C:542–545）。A 的 W13 也说不需要提前建设 profile 编辑器（A:501–508）。但 V2 明确用户应能“回看内容，并控制纠正、遗忘、导出与删除”（V2:19），且初期要有“内容查看与清理”（V2:56）。v1 的“不做编辑器”不能直接带进 v2；v2 需要的是决定控制面的时机与形态。

13. **“记忆控制可以晚点做”与“初期就要有基本查看与清理”。** A 的 W13 说 Internal Core 阶段不需要 profile 编辑器，Pi 式 Manage Memories 留作 External MVP 决策（A:506–508）。V2 说初期具备基本访问控制、内容查看与清理（V2:56）。两者程度不同，v2 的要求更轻但更早。

14. **买 Harness 与“先理解再采用”的学习目标。** N 推荐 Mastra 做运行时，退路是 Vercel AI SDK（N:31–37、N:183–191）。V2 说成熟框架可以采用，前提是理解其架构和关键取舍；旧投入不构成保留实现的理由；下一步共同制定计划后再选 Harness、Memory、数据库和 Provider（V2:11、V2:73）。这不是事实冲突，是顺序冲突。若直接按 N 采用 Mastra，会跳过 V2 要求的学习与共识环节。

### 3.3 证据层冲突与不确定性

15. **full-context 与记忆系统的优劣取决于历史长度。** 短历史 full-context 更强，长历史记忆系统反超（D:524–529）。任何“记忆系统一定更好”或“full-context 足够”的结论都越过了条件。

16. **mem0 与 Zep 的 LoCoMo 之争。** 双方互指配置错误，第三方复测又把 Zep 的数字修正到约 58.44（D:413–425）。任何 LoCoMo 数字必须附配置与切片。

17. **图记忆的收益不确定。** mem0ᵍ 在自家 LoCoMo 上只提升约 2%，MemoryAgentBench 中图谱系整体低于 BM25（D:531–535）。图结构只在关系型问题与时间推理上有确定收益。

18. **异步后台构建有延迟代价。** Zep 的“数小时不可检索”与 Zep 自报的 2.58s 稳态检索延迟并不矛盾，但说明“新信息可见性 SLA”必须在设计里显式处理（D:536–539）。

19. **LoCoMo 的规模口径不一致。** 原论文约 9.2K token 一段，mem0 报告的是约 26K token 的 10 段子集（D:540–541）。复用数字前先核对切片。

20. **A-Mem 的成绩分歧。** mem0 论文中很低，A-Mem 自报显著优于基线（D:542–543）。又一例配置敏感。

21. **NLI 型 groundedness 服务的适用边界。** AWS Bedrock 明示不支持会话型 chatbot，Azure 仅英文优化（D:544–545）。不能直接采购即用。

22. **Tolan 的疗效数字无方法论。** 85.6% “帮助度过情绪困难”、72.5% “改善现实关系”是官网自报，无方法论（A:164–165、A:682）。召回未命中 -30%、次日留存 +20% 也来自供应商案例（A:142–143、B:238）。

23. **Mastra 的 “约 95% LongMemEval” 未复现。** 只追溯到厂商相邻来源，N 明确不据此做预算（N:189、N:573）。

24. **Honcho 官方定价未核实。** 只有第三方数字，选架构 C 前要拿正式报价（N:571）。

25. **“没有多用户消费 App 跑在 OpenClaw 上”是阴性发现。** 专项检索未找到，不等于不存在；N 说 §02 的出局理由不依赖这条（N:113、N:575）。

26. **已发表的 build-vs-buy 证据偏 harness 一侧，companion 一侧很薄。** N 自己把这条列为实验存在的理由（N:577）。

## 4. 不能照搬的假设

### 4.1 v1 的 ADR、产品文档与架构文档不是 v2 的既定约束

四份研究文档大量引用 v1 的 ADR 与文档章节，例如 ADR-0001、0008、0009、0010、0035、0038、0039、0040、0041、0043、0046、0055、0056、0057、0061、0064、0074、0087、0089、0093、0108、0110、0111、0114，以及 product 07–11、14、15、18、19、24–25 与 architecture 07–12、15–17、24–29（A:418–650、B:276–340、C:469–570、D:549–670）。V2 明确说架构、schema、检索限制和发布流程重新评估，旧投入不构成保留实现的理由（V2:11），并且下一步才选择 Harness、Memory、数据库和 Provider（V2:73）。

因此以下都不能当作 v2 的既定前提：

- EvidenceItem、Claim、ClaimVersion、Predicate Registry、Person Portrait、Daily Session、Continuous Exchange、Context Compiler、六层 Prompt、Model Routing、Challenger/Champion 发布机制。
- 预算 v1 的具体数字，例如每轮 memory-class 合计 ≤5、Person Portrait ≤3（其中 AI Impression ≤2）、检索 ≤2、raw Events 4000 token、12 events / 3000 token 摘要阈值。
- 30 天私人 Replay 过期、Internal Context Inspector、1A.3a 退出条件、Phase 2 安全门槛、G2 阶段。
- “现有 seam 足够，不需要改架构”的结论。它只对 v1 已接受的 seam 成立；v2 还没有已接受的 seam，不能用来预先否掉任何设计。

可以带走的不是这些名字和数字，而是它们背后的要求：canonical 归自己、每轮编译上下文、记忆可追溯、用户可纠正、检索精度优先、行为变更可回放。

### 4.2 单用户与内部阶段的简化假设

v1 研究里的 single owner、Internal Core、内部 Inspector、私人 Replay、无外部用户、无年龄边界、无多用户隔离，都是阶段性简化（A:501–515、B:319–330、C:476–530）。V2 要求初期数据归属与访问设计兼容未来多用户（V2:30），并建立测试库与用户库两套隔离数据库，测试不得连接或重置用户库（V2:53–56）。因此以下假设不能照搬：

- “先做单用户，隔离以后再补”。
- “内部工具可以直接读原始内容，不需要访问控制”。
- “测试数据可以来自真实对话”。
- “删除只要删主表”。

### 4.3 技术选型假设

- **PostgreSQL + pgvector 不是 v2 已定选型。** A 与 D 把它当作 v1 已定架构来验证（A:607–618、D:225–237），但 V2 说数据库下一步再选（V2:73）。
- **Mastra、Vercel AI SDK、Honcho、Hindsight、Mem0、Zep、Letta 都不是 v2 已定选型。** N 的推荐是待实验验证的方向，且 N 自己列出 Honcho 定价未核实、Mastra 数字未复现等开放项（N:31–47、N:569–583）。
- **OpenClaw 不能产品化。** N 的证据是它不是多租户系统、一人一实例的单位经济、安全信任假设（N:97–117）。可以作为个人工具或设计参考，不能作为 v2 的多用户运行时。
- **Vercel 部署可以保留。** V2 明确 Web 部署到 Vercel（V2:28、V2:47），这一条不属于“未定选型”。

### 4.4 产品语义假设

- **Profile 是自然语言 Bio、用户不可直接编辑。** 这是 v1 的 ADR-0055/0057。V2 说 `fact`、`opinion`、`profile` 是待澄清的概念，不预设为互斥类型或数据库表，schema 与 Reflection 组织在相应阶段决定（V2:60）。不能把 Bio/Claim 二分直接带过来。
- **不做记忆编辑器。** V2 要求用户能回看、纠正、遗忘、导出、删除（V2:19），初期要有内容查看与清理（V2:56）。编辑器形态可以晚定，但“不做”不能作为 v2 的默认。
- **不做对话外主动消息。** v1 的 ADR-0043 不能直接约束 v2。V2 把 Open Loop 与适时跟进列为长期方向（V2:19），但没有决定是否允许对话外消息。这是开放决策，不是已拒绝项。
- **Open Loop、完整纠正与遗忘、日记、实时语音、完整多用户都后置。** 这是 V2 自己的排序（V2:30），与 v1 的 1A.3a 阶段划分不是同一套。不要把 v1 的“1A.3a 必须包含 X”当成 v2 的首期范围。
- **“每轮最多一问”是 v1 的严格选择，不是行业验证的结论。** 行业没有任何一家公布量化追问政策；Tolan 只有 `question quality` 与 `or-questions` 作为 eval 类别（A:21–24、A:446–458）。可以作为 v2 的待验证设计假设，不能当成证据。

### 4.5 研究结论的时效与范围

- 四份研究文档的抓取日期是 2026-08-21 至 2026-08-24。ChatGPT、Gemini、Claude 的记忆形态在 2025–2026 变化很快，C 自己就标注了多个时间点（C:83–85）。v2 若引用具体产品行为，应先复核第一方页面。
- 四份文档都声明自己是研究输入而非决策（A:3、B:3、C:3、D:3）。引用时应引“证据”，不要引“结论”。
- 负向发现是“查无”，不是“不存在”（A:668–683、N:569–583）。
- 供应商案例是单源，Tolan 的多数实现细节来自 OpenAI 官方案例中的团队自述（A:122–143、B:231–238、D:494–495）。
- N 的核心论证“以前 AI 调研都说自建更好，是因为五个系统性偏差”本身是论证，不是测量。五个偏差可以作为阅读未来调研的检查表，不能当成已被证实的规律（N:49–73）。
- N 的 “80/20 墙” 与 “60% 框架 / 40% 自建” 来自一位开发者的一手经验，不是普遍规律（N:75–79）。

### 4.6 评测与实验假设

- **基准排行榜不能作为选型依据。** 这是四份文档的共同结论（N:319–336、D:413–425）。v2 可以把基准用作工程冒烟，不能用作产品验收。
- **两周实验的阈值是 v1 语境。** “盲评高 ≥0.5 分或工时少 ≥40% 就买入”是 N 为 v1 定的规则（N:563–567）。v2 可以复用实验设计、语料和打分维度，不应直接复用阈值。
- **“买入”与 v2 的学习目标可能冲突。** 如果买入意味着 Luke 无法解释内部结构、运行机制和关键取舍，就违反 V2 的学习定义（V2:34–43）。采用任何框架前，先确认它能被理解、能被替换、能被验证。

## 5. 对 v2 的直接含义

可以当作要求带走的内容：

- canonical 数据归自己，原始消息、AI 产物与来源可区分，派生索引可重建（V2:26、V2:58；N:416–418；D:24–30）。
- 每轮从 canonical 与检索结果编译上下文，不把模型会话当长期状态（A:469–475；D:494–495）。
- 记忆抽取先轻后重，先 canonical 与基础召回，再异步整合与 Reflection（V2:30；D:554–564）。
- 记忆条目离散、可版本化、显式 supersede，不做静默改写或静默删除（D:219–223、D:400–411；V2:58）。
- 检索精度优先，混合检索与结构化过滤优先于复杂图谱（D:254–256、D:297–300、D:531–535）。
- 召回无仪式，归因按需，运行详情可展开（C:19–23、C:407–415；V2:28）。
- 评测用产品内盲评、小失败集、内容无关遥测，不用排行榜选型（A:519–532；C:449–463；D:427–442）。
- 多用户隔离、删除实测、记忆注入视为不可信输入，从第一天设计（N:406–414；V2:30、V2:53–56）。
- 导出、删除、查看、清理从初期成立（V2:19、V2:56）。
- 人格边界保留：非人类、不恋爱、不排他、不制造依赖、反谄媚、先倾听（V2:17）。

需要 v2 明确裁决的开放项：

- 是否允许对话外主动跟进，以及它与“不制造依赖”的边界（N:93 与 A:565–570 冲突；V2:19 未决）。
- 记忆控制面的形态与时机，尤其是“查看、纠正、遗忘”在首期做到什么程度（V2:19、V2:56 与 A:501–508 的差异）。
- 年龄边界与危机处理是否进入 2026 年范围（A:672–674、B:325；V2 未提）。
- 测试库与用户库的隔离机制、测试数据生成方式、私人对话不进入测试集的具体规则（V2:53–56）。
- Harness、Memory、数据库、Provider 的选择顺序与学习路径（V2:11、V2:73；N:31–47 只是候选）。
- 存储形式是 Postgres、文件，还是混合；不变量是 canonical 归自己，形式可后定（N:296、N:305 与 A:607–618 的冲突）。
