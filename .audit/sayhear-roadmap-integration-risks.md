# 计划写作时必须处理的风险

- canonical 数据不能晚于人格或记忆。任何候选把它推到后面，都需要重排。
- 工具调用是 CONTEXT 明确的年底目标，不能改成可选。低风险工具可用来验证机制，工具用途和最小场景阶段启动时确定。
- Reflection 是年底目标，不能默认删掉。若时间不足，缩小自动化和检索复杂度；调整目标必须与 Luke 明确讨论。
- 初期内容查看与清理属于已定要求。完整纠正与遗忘后置，不代表早期可以保留已删除内容继续召回。
- 数据库分支可能复制生产数据，不作为测试与用户库隔离的默认方案。应使用独立实例与凭据，并核对安全重置边界。
- 旧 Portal 的日期和会话表达可能包含产品体验规则。计划只能指出耦合，不能未经 Luke 共识擅自删除日期导航或改变会话体验。
- 初期可以只有 Luke 一个真实用户，但授权与归属边界要能用两个合成主体检验；不能把完整多用户上线提前。
- 框架安装、合成对话回放、线上日常体验和 Luke 的理解属于不同证据，不互相替代。
- 模型和第三方工具输出都不能直接升级成用户事实。记忆文本也不是系统指令。
- 框架能力、服务发布状态、价格和 Provider 协议会变，阶段启动核查选定版本和条款；不在计划中假设其永远不变。
