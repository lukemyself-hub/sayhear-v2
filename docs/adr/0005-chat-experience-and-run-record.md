# 聊天中断、fallback 可见性、登录方式与运行记录的初期体验

Luke 于 2026-10-22 确认以下用户可见行为：

- 生成中途被用户停止或出错时，保留已显示的部分回答并标注中断，交互复用旧 Portal。
- 自动切换到 fallback Provider 时，聊天界面不提示；运行详情标明实际使用的 Provider 与是否发生切换。
- 自用阶段登录采用 Supabase Auth 的邮箱 + 密码。
- 运行记录自建并存于 SayHear 数据库，不把对话内容发往第三方观测平台。运行记录须直观、简洁，初期只保存定位问题所需的少量字段，避免难懂的术语与过度结构化。

相关决定见 [ADR 0001](0001-database-and-managed-auth.md)、[ADR 0003](0003-provider-phasing-and-fallback.md) 与 [ADR 0004](0004-harness-on-ai-sdk.md)。

## 取舍与边界

保留部分回答使中断内容可回看，但部分回答须与完整回答可区分，后续构造上下文时如何使用部分回答在阶段 1 SPEC 中确定。界面不提示 fallback 使聊天体验保持安静，代价是只有打开运行详情才能看出回答来自哪个 Provider。邮箱 + 密码依赖密码找回邮件，Supabase 默认邮件服务的发送限制需在实施时核实。运行记录至少能回答：模型收到了什么、选中了哪些历史或记忆、用了哪个 Provider、哪里失败。

## 主动停止在首段前后的语义

Luke 于 2026-10-24 回复“认可，继续”，接受首段正文出现前主动停止也将 run 记为 `interrupted`，结束原因为用户停止；不创建空 assistant 消息，不自动 fallback。有部分正文时，继续沿用保留部分回答并标注中断的决定。

这样主动停止在首段前后有一致语义，并可与系统失败区分。`interrupted` 表示运行未正常完成，不表示一定已有部分正文；是否存在回答由消息记录表达。状态与结束原因分开记录，不为每种中断原因新增状态。具体取消信号、停止与完成竞态、保存失败及崩溃恢复仍由 M4 的执行契约细化，本决定不把未验证的停止行为写成已实现。

## 单条消息删除与历史快照

2026-10-24 更新：Luke 明确接受“删除一条消息，之后运行详情里就无法再显示被删除的原文”。这取代此前为完整回看而保留被删消息快照正文的要求，理由是避免为这项能力重复存储大量历史内容。具体引用结构仍待 ADR 0010 的后续设计，不能仅凭此决定宣称已能准确重建完整请求。

单条消息删除后，聊天及历史运行详情均不再显示该消息的原文，后续模型输入排除它。运行记录仍可保留该消息的标识、当时是否选中及所在顺序，并明确标注原文已删除，不能伪装成仍可完整还原。run、attempt 与其他未删除内容不因这条删除而一并清除；运行记录仍按 owner 隔离，只用于回看排查，不作为后续模型输入来源。派生内容、备份及 Provider 保留边界继续由相应模块细化，不将这一回看决定扩展为所有副本已彻底清除的承诺。

删除生效后的新上下文与新输入快照不得再次纳入该消息。此要求包括历史选择、检索与从旧快照回放等路径；以后引入摘要或记忆时，需定义避免该消息通过派生产物重新进入上下文的规则。该操作不等同于彻底遗忘所有相关事实，其他未删除消息可能包含相同信息。正在执行的请求如何处理在实施规格中明确，不宣称能撤回已经发给 Provider 的输入。

删除后的界面提示仅为“该消息已删除”，不附加模型使用与快照保留机制的说明。整账户清理仍沿用清理所有该用户消息、运行及输入快照的独立契约，不因单条删除语义而改变。

## 暂缓：生成中删除回答不作为当前界面必决场景

2026-10-24，Luke 澄清界面中没有删除正在生成的 assistant 回答的选项，发送后输入框的停止按钮用于停止当次生成。主 Agent 因此前草案提到生成中删除而将其升级为当前必决问题，超出了已确认界面场景；现撤回该确认问题，不新增删除入口，不阻塞 M2。v2 尚未实现，本段依据 Luke 对目标交互的澄清，不冒称已验证真实界面。

当前沿用已接受的停止语义：停止按钮请求停止当次生成，run interrupted，不 fallback；已有部分回答保留并标记中断，停止本身不清空正文或设置 deleted_at。Provider 结果按实际证据记录，取消传播与计费边界仍由 M4 验证。已结束消息的删除是另一项操作，沿用清空、占位和运行详情不再显示原文的契约。

若 M5/M7 后续明确提出生成中删除入口，或核实实际允许的操作确实会触发这一场景，再重访是否同时停止。此前“删除即停止”只是主 Agent 未获接受的推荐，已暂缓；本次也不擅自决定 API 是否接受该操作，不将无界面入口当作所有删除竞态已验证。
