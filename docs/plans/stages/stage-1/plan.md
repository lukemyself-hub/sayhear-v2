# 阶段 1 总计划

补录日期：2026-10-24。Luke 同日明确认可本计划的九个模块，以及先继续 canonical 数据结构、再按依赖细化其余模块的安排。此确认不等于接受表内尚未决定的技术方案，也不授权实现；既有范围和 Accepted ADR 继续有效。此前没有阶段总计划，本文件不追记为过去已确认的计划。

## 依据、目标与边界

范围真源为 [Issue #1](https://github.com/lukemyself-hub/sayhear-v2/issues/1)，本次已读取其 2026-10-23 更新的正文、标签及评论。规划同时依据 [CONTEXT.md](../../../../CONTEXT.md)、[路线图的阶段 1](../../roadmap/sayhear-build-and-learning-plan.md#阶段-1-建立基础对话与-canonical-闭环)、[ADR 索引](../../../decisions.md)中的 ADR 0001–0015，以及已有[身份](features/identity-data-ownership/session.md)与[数据结构](features/canonical-data-model/session.md)记录。这里组织需求及讨论顺序，不复制完整 SPEC，也不新增产品要求。

体验目标是 Luke 能在开发电脑离线时使用私有 Web 聊天，连续保存和查看历史，停止或失败时保留诚实状态，并沿运行详情追溯模型输入与回答来源。

本阶段覆盖身份隔离、canonical 数据、近期上下文与日期、流式执行、聊天界面、运行详情、清理、合成数据与验收、托管运行与恢复。找回密码、公开注册、完整多用户管理、长期记忆与摘要、Reflection、人格打磨、实际工具循环、Journal、语音及 Open Loop 不在本阶段。排队功能尚未确定是否纳入，不因存储兼容性讨论自动加入范围。

本次授权仅为建立讨论分支、补齐必要文档和继续讨论；不包含产品实现、安装工具、测试执行、资源创建、用户库访问、部署、Issue 写入或 Git 发布。

## 共享契约与讨论顺序

| 契约 | 主要归属 | 协作与收口条件 |
| --- | --- | --- |
| 身份、owner、RLS、环境与凭据 | M1 | M2 为真实表逐项覆盖；M4 兑现长流续期与保存；M9 遵守迁移和凭据边界 |
| 消息、run/attempt、来源、格式与 seq | M2 | M4 定执行终态，M5 定事件合并和显示，M6 定快照；消息排序不能代替输入证明 |
| 历史选择、指令来源、预算和日期 | M3 | M2 提供存储语义，M4 组装和发送，M6 保存实际副本；不把旧快照作为新上下文来源 |
| 停止、错误、幂等、checkpoint 与恢复 | M4 | M2 约束状态和数量，M5 如实显示，M6 定位失败，M7 防删除内容恢复 |
| 删除生效、快照保留与账户清理 | M7 | M1 控权限和撤销，M2 保数据库约束，M3 排除后续输入，M9 说明备份与外送保留 |
| 数据集、验收证据、运行指标与版本 | M8 | 所有模块提供自己的场景；M6 产运行证据，M9 补真实托管证据，不用一种环境替代全部验证 |

Luke 已确认本次补录的九个模块及先继续 M2、再按依赖细化其余模块的安排。系统记录、合成搜索边界、会话最小结构、主动停止与失联恢复语义、输入快照布局已分项接受；当前进入快照字段与捕获时序，并继续补齐 run/attempt 字段、消息约束、seq 与格式版本。与 M3/M4/M6/M7 相交的问题在契约归属处确认，局部记录链接，不重复表决已接受决定。

M2 后按依赖细化 M3、M4，再整合 M5、M6、M7。M8 从讨论开始登记覆盖缺口，M9 的资源与运维方案在交接前收口。此为讨论顺序建议，不授权开始实现，也不推定身份模块实施顺序已确认。新发现改变阶段范围时先与 Luke 确认。

每个模块的设计收口需能链接决定、未决项、正常及失败场景、学习回访。所有构建、开发及体验决策建立或关联 ADR。阶段总 SPEC 以既有 Issue #1 为承载候选，细化或发布前需相应授权，不能建立竞争的范围真源。
