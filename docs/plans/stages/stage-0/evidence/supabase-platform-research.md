# Supabase 平台核查（auth / 计费 / 备份 / SDK）

核查日期：2026-10-22；同日补测四个 Auth/MAU 参考页。方式：仅官方来源，10 次获取，全部为定价页、备份文档、Auth MFA 文档、Auth server-side 文档、Auth 三个参考页、MAU 页、两个 npm registry。未读仓库其他部分，未安装依赖，未连接账号。
范围：只回答 auth 与成本相关的核查问题。与既有 `stage-0-data-and-delivery-evidence.md` 的 Supabase 段交叉核对，冲突处显式标出。

## 2. 备份与 PITR

| 项 | 结论 | 来源 |
| --- | --- | --- |
| Pro 每日备份保留 | 确认：“Pro Plan projects can access the last 7 days of daily backups.”（Team 14 天，Enterprise 最多 30 天） | 备份文档 |
| Free 备份 | 确认 Free 无每日备份保留，官方让免费层用户自己用 CLI 存数据 | 备份文档 |
| PITR 可用性 | 确认：“Pro, Team and Enterprise Plan projects can enable PITR as an add-on.” | 备份文档 |
| PITR 价格 | 确认 7 天 $0.137/小时、约 $100/月；14 天约 $200；28 天约 $400 | 备份文档 |
| PITR 最低 compute | 确认：“Projects that want to use PITR must also use at least a Small compute add-on to ensure smooth functioning.” 注意是 **Small 而非 Large**；既有文档写“至少 Small 计算”与此一致 | 备份文档 |
| PITR 与每日备份互斥 | 确认：“If you enable PITR, we will no longer take Daily Backups.” | 备份文档 |
| Storage 对象 | 确认不含：”Database backups do not include objects you store via the Storage API.” 且”Restoring an old backup does not restore objects you deleted after that backup.” | 备份文档 |
| auth schema 是否在备份内 | **unknown**。备份文档没有提 `auth.users`。它只排除”custom roles 的密码”（”daily backups do not store passwords for custom roles”，恢复后需重置），不涉及内置 auth 用户表。不能从该页推断 auth.users 在或不在备份内。合理推断是 auth schema 属 Postgres 数据因而在库级备份范围内，但这是推断，不是保证 → 需在恢复演练中核实 | 备份文档 |
| Storage 恢复含义 | 数据库备份不能恢复 Storage 对象，恢复旧备份不会找回该备份后被删的对象。这不等于”删除即绝无恢复可能”：需独立的 Storage 备份/对象版本策略，不能因库备份不含对象就断定对象永久不可恢复 | 备份文档 |

与既有证据文档的一致性：既有 `stage-0-data-and-delivery-evidence.md` 第 38 行“Pro 每日备份保留 7 天；PITR 为附加项，7 天约 $100/月，且需至少 Small 计算”与本次核查一致，无需修正。

## 3. Auth 能力

| 能力 | 结论 | 来源 |
| --- | --- | --- |
| MFA 支持 | 确认。官方原文：“Supabase Auth implements MFA via two methods: App Authenticator”与“and phone messaging, which makes use of a code generated by Supabase Auth.”；“You can combine both flows and allow for use of both Phone and App Authenticator Factors.” WebAuthn 未提及 | auth-mfa 文档 |
| MFA API | 确认有 Enrollment API、Challenge and Verify APIs、List Factors API；移除因子原文：“When a user unenrolls a factor, call `supabase.auth.mfa.unenroll()` with the ID of the factor.” | auth-mfa 文档 |
| Phone MFA 价格 | auth-mfa 页无价格；定价页确认 Advanced phone MFA $75/月首项目 + $10/月每增项目 | 定价页 + auth-mfa 文档 |
| 改邮箱 | 已核：登录用户通过 `updateUser({ email })` 更新邮箱。该用户接口不要求 `service_role`；不得混淆用户操作与管理员操作 | https://supabase.com/docs/reference/javascript/auth-updateuser |
| 删除用户 | 已核：`deleteUser()` 为服务端 Admin API，要求 `service_role`。`shouldSoftDelete` 官方说明为 "Defaults to false for backward compatibility"；可选 soft delete 也标为不可逆 | https://supabase.com/docs/reference/javascript/auth-admin-deleteuser |
| 恢复/重置密码 | ✅ 已核（2026-10-22 补）。`resetPasswordForEmail()` 支持找回流程。官方原文：”Sends a password reset request to an email address.”（可选 `redirectTo`）。配套流程页确认密码恢复为内置 Auth 能力 | https://supabase.com/docs/reference/javascript/auth-resetpasswordforemail |
| MFA 支持 | 确认。官方原文：”Supabase Auth implements MFA via two methods: App Authenticator”与”and phone messaging, which makes use of a code generated by Supabase Auth.”；”You can combine both flows and allow for use of both Phone and App Authenticator Factors.” WebAuthn 未提及 | auth-mfa 文档 |
| MFA API | 确认有 Enrollment API、Challenge and Verify APIs、List Factors API；移除因子原文：”When a user unenrolls a factor, call `supabase.auth.mfa.unenroll()` with the ID of the factor.” | auth-mfa 文档 |
| Phone MFA 价格 | auth-mfa 页无价格；定价页确认 Advanced phone MFA $75/月首项目 + $10/月每增项目 | 定价页 + auth-mfa 文档 |
| MAU 计数口径 | 已核：计费周期内登录或刷新 token 的不同用户。跨 project 去重与聚合计费细则未由本轮原文明确，不从 Usage 页面可查看所有项目推断去重方式 | https://supabase.com/docs/guides/platform/manage-your-usage/monthly-active-users |
| Auth 用量可见性 | ✅ 已核（2026-10-22 补）。MAU 页：”You can view your project's usage on the [Usage] page”，即各 project usage 可看；但可见 ≠ 已说明跨 project 计费口径 | MAU 页 |

产品含义：`CONTEXT.md` 要求”用户应能控制纠正、遗忘、导出与删除”。删除用户账号与删除其数据是两件事：账号级删除走 Auth API（soft delete 不可恢复，永久删除须显式 `shouldSoftDelete: false`），数据级删除走数据库与 Storage。MFA 若采用 phone 因子会产生固定月费（$75 起），与”初期只有 Luke 一个用户”的规模不匹配；App Authenticator（TOTP）因子无此附加费。

## 4. SDK 版本与稳定性

| 包 | 版本 | 稳定性判断 | 来源 |
| --- | --- | --- | --- |
| `@supabase/supabase-js` | 2.118.0（`latest` tag） | stable。registry 另有 `beta`(2.112.0-beta.0)、`rc`(2.100.0-rc.0)、`next`(3.0.0-next.29)、`canary`(2.119.0-canary.1) 等 tag，`latest` 不是预发布 | npm registry |
| `@supabase/ssr` | 0.12.7（`latest` tag） | **beta，官方明确**。官方原文：”This package is currently in beta.” 与”Adoption is recommended but be aware that the API is still unstable and may have breaking changes in the future.” 不得据此宣称”Supabase 全栈稳定”——主 SDK stable，SSR 包 beta | npm registry + server-side 文档 |

server-side 用法确认：官方推荐用 `@supabase/ssr`，“We have developed an `@supabase/ssr` package for setting up the Supabase client.”；SSR 需要“the user session in cookies instead of local storage”；Next.js quickstart 承诺“Automatically configure Supabase in Next.js to use cookies.”该页未点名 `createServerClient`，函数名需在 Next.js 专页核实（本次未取，标需补）。

## 5. 明确缺口（未取得官方原文，不猜）

1. MAU 跨 project 去重与聚合计费细则未明确，采用前按实际组织账单核对。
2. `auth.users` 是否包含在每日备份与 PITR 内——备份文档未提。合理推断包含，需在恢复演练中核实。
3. `createServerClient` 的确切签名与 Next.js 中间件刷新会话写法——需补 Next.js 专页。
4. Auth 用户表是否计入”database size / 8 GB disk”与”500 MB”额度——定价页未明说。
5. 删除身份后既有会话与业务派生产物的失效行为，仍需应用验收；soft delete 不能当作账户恢复功能。

## 6. 建议的影响面

- 成本下限：Pro 25 + 每项目 compute 10，含 10 美元 compute 抵扣，两个项目合计约 $35/月；单项目约 $25/月（抵扣覆盖唯一 Micro）。免费层默认无每日备份保留（官方让免费层用户自己用 CLI 存数据），因此**就默认托管保障而言**，Free 不提供恢复窗口；若配合独立的导出/备份脚本，Free 并非绝对不可行，但恢复能力落在自建脚本上而非平台。
- 若选 Supabase，备份默认只有 7 天每日备份；PITR 另加约 $100/月且要求至少 Small compute，并会替换掉每日备份。**7 天是平台保留期，不是 RPO，也不是 Luke 已确认的业务恢复目标**；可接受性需要业务恢复目标来判定，SPEC 中应写明目标而非假定此下限足够。
- 采用 phone MFA 会带来 $75/月固定成本，不建议初期启用；TOTP App Authenticator 因子无附加费。
- Storage 对象不在数据库备份内。若产品未来存语音/附件，删除后无法从库备份恢复，需要独立的 Storage 备份/对象版本策略与删除确认、导出路径；不能据此断定对象绝无其他恢复途径。
