# 调研与委派

## 定点调研

开始前写清问题、它影响哪个议题、证据要求和停止条件。通常比较成熟主选和最强替代，足以决策即停；只为会改变选择的重要未知扩大调查。

优先当前官方资料、固定版本源码和实际观测，区分文档能力、推断和实测，并标注置信度。采用前重核易变事实；旧仓库的结论不直接成为 v2 共识。资料无法回答且影响决定时，设计有限验证和停止条件，交给相应工作流执行，本 skill 不做构建与测试。

结果写回议题清单：结论和证据链接，或明确的未知及其影响。

## 工具

`how` 查机制，`why` 查设计依据，`research` 查外部事实。这些技能各自写明如何适配 Claude Code、Codex 等运行时；从当前运行时实际安装的位置调用，不写死路径或缓存版本。只使用这些技能本身，不进入 `poteto-mode` 的 playbook 或构建流程。

## 委派

独立的批量阅读、专项调查和反方检查交给 worker，主会话继续对话；小而紧耦合的查阅自己完成。委派工具和 fallback 顺序以当前运行时的全局与仓库指令为准，例如 Codex 全局指令默认用 `delegate-claude`，Claude Code 可用原生 subagent。没有可用的委派方式时自己完成，并在接续记录里说明。

任务书写明目标、授权边界、文件指针、证据要求、独立输出位置和完成条件。worker 不写阶段状态、SPEC 或学习索引，只返回摘要、证据指针、未知与限制。主 Agent 读结果和 warnings，核实影响决定的证据，不以 `completed` 代替验证。活跃委派登记在接续记录。
