## Problem Statement

Luke 要在 SayHear v2 里只让自己能登录并只读写自己的聊天，同时让自动化测试永远碰不到真实用户库。旧仓库的教训是：owner 只靠应用代码过滤、RLS 缺位，漏写一处过滤就会泄露私人对话；而且"应用入口拒绝了越权"会被误当成"数据已经安全"。阶段 1 需要一个可验证的身份与隔离边界：owner 从哪里来、哪一层负责拒绝越权、登出之后旧 cookie 还能不能读写、测试凭什么连不上用户库——每一层都要有独立的、可复现的证据，而不是靠代码看起来写对了。

## Solution

从用户视角：Luke 在控制台开通的账号上用邮箱密码登录后，只能看到自己的会话与消息；登出后，之前复制下来的 cookie 立刻不能再读写任何私人数据；测试只在本地栈或云端测试项目里用合成主体运行，配置错配时在写入前就停下。服务端从可信认证取得用户身份，以该用户令牌经 Data API 访问数据库，RLS 作为漏写过滤时的兜底；每条 owner 作用域记录直接带 owner 列，跨表引用用同 owner 组合外键约束；身份适配框架（登录、会话、登出、入口检查、身份注入）可以先做到可验收，与尚未收口的物理 schema 解耦。

## User Stories

1. 作为唯一真实用户，我想用邮箱密码登录自己控制台开通的账号，以便在不开放注册的前提下独占使用 SayHear。
2. 作为唯一真实用户，我想在关闭公开注册的环境里自行注册会被拒绝，以便没有陌生账号进入我的数据。
3. 作为唯一真实用户，我想登录后浏览器只访问我自己的应用域名，以便令牌与 cookie 不经过第三方前端。
4. 作为唯一真实用户，我想会话在服务端用锁定版本的 `@supabase/ssr` 维护并在续期时回写 cookie，以便长回复期间会话不中断。
5. 作为唯一真实用户，我想 access token 到期但 refresh token 仍有效时请求经真实续期路径完成，以便不被无谓踢出登录。
6. 作为唯一真实用户，我想令牌无法续期或续期后仍不足以覆盖本次运行预算时，请求被拒绝且我能重新登录，以便不带着坏会话继续操作。
7. 作为唯一真实用户，我想长回复在输出第一段之前就确保令牌有效期覆盖运行预算与收尾余量，以便回复不会被自己的过期令牌打断。
8. 作为唯一真实用户，我想登出后新发起的私人数据请求立即被拒绝，以便拷贝出去的 cookie 立刻失效。
9. 作为唯一真实用户，我想登出前已经开始的回复能在原时间预算内完成并保存，以便我不必为了登出牺牲正在进行的回答。
10. 作为唯一真实用户，我想退出后原浏览器确实处于已登出状态，以便换设备或共享屏幕时没有残留会话。
11. 作为唯一真实用户，我想私人数据请求一律动态渲染且 `Cache-Control: private, no-store`，以便共享设备或中间缓存不回放我的内容。
12. 作为唯一真实用户，我想提交请求时不能用伪造 owner 或他人的资源标识访问或修改数据，以便别人无法把数据写到我名下或指定归属。
13. 作为唯一真实用户，我想应用代码漏写 owner 过滤时读取结果为空、写入被拒绝，以便单点疏漏不导致泄露。
14. 作为唯一真实用户，我想子记录（run、attempt、assistant 消息、输入快照）引用父记录时受同 owner 组合外键约束，以便没人能把自己的记录挂到我的消息下。
15. 作为唯一真实用户，我想"保存用户消息 + 创建 run + 创建 attempt"这类原子写由一个受 RLS 约束的数据库函数一次完成，以便不会出现半套记录。
16. 作为唯一真实用户，我想同一请求重复提交不产生第二个 run，以便传输重发不污染运行记录。
17. 作为唯一真实用户，我想删除 auth 用户后各表一次级联清除，以便账户清理不留孤儿数据。
18. 作为唯一真实用户，我想单条删除把消息行改成"已删除"占位并清空原文，以便历史里不留可读内容但来源链不断。
19. 作为开发者，我想特权操作（开通账号、删除 auth 用户、测试合成主体装载、备份）集中在独立模块且不进请求路径，以便用户令牌路径不被高权限凭据污染。
20. 作为开发者，我想在关闭注册下由控制台手动创建并确认邮箱的合成账号可以密码登录，以便测试不依赖自助注册。
21. 作为开发者，我想在隔离环境里控制令牌有效期并观察真实续期与 cookie 回写，以便验收不是 mock 出来的。
22. 作为开发者，我想用合成主体 A 的用户令牌直接请求 Data API 读写 B 的数据，以便证明 RLS 兜底而不是只证明应用入口。
23. 作为开发者，我想用 A 的记录引用 B 的父记录被约束拒绝，以便证明组合外键真的生效。
24. 作为开发者，我想混配 URL/key/期望 ref/环境身份记录时业务写入前就中止，以便配置错贴不会写到用户库。
25. 作为开发者，我想模拟 `user` 目标的破坏性测试只能指向隔离合成目标，以便真实用户库永不被测试触碰。
26. 作为开发者，我想迁移经包装脚本执行并在本地重放、云端演练后才允许用户库操作，以便结构变更顺序可控。
27. 作为开发者，我想云端测试项目完成迁移演练、Preview 登录/续期/读写/登出冒烟，以便托管环境与本地差异被发现。
28. 作为开发者，我想 A/B 两个合成主体交替访问时不串用身份也不命中对方缓存，以便多用户早期的隔离假设成立。
29. 作为开发者，我想聊天主链路（身份确认 → 续期 → 原子写 → 流式响应）放在不依赖框架的服务端模块里，以便将来换框架只重写页面层。
30. 作为学习者，我能沿一次请求解释 owner 从哪里来、谁在哪一层拒绝越权、测试为什么连不上用户库，以便本阶段的学习目标达成。
31. 作为审阅者，我想看到每项验收的未运行/失败/被阻塞分别记录，以便不会把"没跑"读成"通过"。

## Implementation Decisions

1. **数据访问路径（ADR 0009）**：服务端用锁定版本的 `@supabase/ssr` 从 cookie 取得并验证用户会话，以该用户令牌经 supabase-js（Data API）访问数据库；数据库以 `authenticated` 角色执行，所有 owner 作用域表启用 RLS，策略比对每行 `owner_id` 与 `(select auth.uid())`。查询侧仍显式按 owner 过滤，RLS 是兜底而非唯一防线。不使用绕过 RLS 的凭据走请求路径，也不把 Secret key 交给浏览器。
2. **原子写与幂等（ADR 0009/0010）**：多表原子写由一个 `security invoker` 的 Postgres 函数完成，函数只做原子写与幂等判断，不承载上下文选择、Provider 或重试等业务逻辑；函数与服务端分开发布，接口薄而稳定，先执行迁移再部署服务端。幂等靠 owner 作用域唯一约束。迁移以 Supabase CLI SQL migration 为单一真源，RLS 与授权语句一并纳入。
3. **特权通道（ADR 0009/0011）**：Secret key 只用于没有用户令牌的少数操作——关闭注册下开通账号、账户清理删除 auth 用户、测试合成主体装载、备份——集中在独立模块，不进入请求路径的通用客户端。
4. **令牌预算与续期（ADR 0009/0011/0014）**：请求开始时确认用户令牌剩余有效期覆盖本次运行预算与保存收尾余量（沿用 ADR 0006 低于 300 秒的总预算），并避开锁定 SDK 的临期自动刷新窗口；不足先续期，续期与 Set-Cookie 必须在返回流式响应前完成。续期后仍不足或续期失败，不启动生成。仍以用户身份写入，不切换特权凭据，不依赖 SDK 流中刷新兜底。
5. **最小数据契约（ADR 0010）**：owner 即 Supabase Auth 用户 ID，不另建应用账号表。阶段 1 的 owner 作用域记录（连续会话、消息、run、attempt、输入快照）每类直接带 `owner_id`，不通过连表推断归属。子记录引用父记录时以 `(owner_id, 父 id)` 组合外键约束同属一人，只在真实存在的引用上使用。引用关系与数量、run 的 `(owner_id, 客户端请求标识)` 唯一约束、账户清理级联、单条删除清空原文不级联，均按 ADR 0010 的表格与语义执行。
6. **输入快照（ADR 0010/0005）**：输入快照按 attempt 归属，保存实际发送内容的副本，不用消息 id 引用代替；单条删除不清空快照副本，按 owner 隔离保留。快照与 attempt 是拆表还是合并为 attempt 的一列**本文不裁定**，留待 canonical 数据模型收口；两种做法都不改变上述归属与删除语义。
7. **登录生命周期（ADR 0011）**：阶段 1 只做账号开通、登录、续期、登出；找回密码延后，因此不发送邮件、不依赖 SMTP。关闭公开注册，Luke 的账号由人在用户项目控制台手动创建并标记邮箱已确认，应用不提供开通入口也不持开通凭据；测试项目的合成主体由测试装载流程经特权通道创建。浏览器只访问应用域名；认证响应设 `Cache-Control: private, no-store`；Supabase client 每个请求新建；服务端不以 `getSession()` 作为身份依据。
8. **登出语义（ADR 0011/0013）**：读写私人数据的请求在服务端入口用 `getUser()` 向 Auth 确认会话仍然有效，再用该用户令牌访问 Data API；不读写私人数据的请求可用 `getClaims()` 本地验签。登出成功后新发起的私人数据请求立即拒绝；已通过入口检查并开始的回复允许在原预算内完成和保存。不新增运行中撤销轮询，入口检查不等于整个流期间持续检查撤销。**不以调用了 `getUser()` 等函数推定登出重放验证通过**：结论以实际行为为准（ADR 0013）；若锁定版本不检查会话撤销，须回到 ADR 0011 补足会话存在性检查，不得降低已确认的验收标准。
9. **测试环境与三道护栏（ADR 0012）**：本地 Supabase 栈承担自动测试、RLS 越权验证、Auth 生命周期与合成数据装载；云端测试项目承担迁移演练、Vercel Preview 冒烟与恢复演练，只含合成数据；用户项目只做真实使用，Vercel Production 指向这里。三道护栏——凭据隔离（测试装载工具只读测试专用变量，缺失即退出，不回退应用变量）、写入前核验目标身份（期望 ref 比对 + 只读 sentinel 探测，缺失/读取失败/信号矛盾一律 fail closed，均拒绝 `user`）、迁移操作隔离（统一包装脚本，本地重放 → 云端演练 → 独立授权后用户库执行，用户库推送须显式选择项目、先 dry-run、Luke 确认）。
10. **验收分层（ADR 0013）**：应用入口、数据库、环境护栏、部署链路四组独立验收，互不替代。应用入口拒绝越权不能证明数据库兜底有效。每项证据记录环境、版本、前提、动作、预期和实际结果并核对写入前后状态；cookie、密码与令牌不进仓库、日志或截图；未运行、失败、被环境阻塞分别记录。
11. **Web 框架（ADR 0014）**：Next.js App Router，服务端代码跑 Node runtime，版本实施时锁定。三条护栏：续期与 Set-Cookie 只出现在 Proxy 与 Route Handler，Server Component 只读数据不承担续期；读写私人数据的页面与接口一律动态渲染并设 `Cache-Control: private, no-store`；聊天主链路放在不依赖 Next 专有 API 的服务端模块，只接收标准 `Request`、返回标准 `Response`，Route Handler 只负责转交。v1 只复用外观与交互设计（视觉规则与尺寸、DOM 结构、交互状态机、设计契约测试、视觉验收脚本），不搬用完整页面代码；登录、会话、数据装载、流式事件协议按 v2 决定重建。
12. **与物理 schema 的解耦**：身份适配框架（入口身份确认、续期、身份注入、特权通道、环境护栏、验收脚手架）可以先做到可验收，不依赖 canonical 数据模型的表结构。真实 schema 下的**所有表覆盖**——每条 owner 作用域表的 RLS 策略、每个引用的组合外键、原子写函数、删除与级联行为——依赖兄弟草稿 [`../canonical-data-model/session.md`](../canonical-data-model/session.md) 收口后逐表提出，本文不预先裁定表名与列。
13. **流式 checkpoint 集成**：checkpoint 写入与流式响应的集成待聊天实现落定。本文相关条目（续期后跨过原令牌到期时刻 checkpoint 仍成功、原预算内完成保存）在本轮记为 **not run**，逐项列出，不以任何形式的推断或代码审读替代运行证据。

## Testing Decisions

- 好测试的标准：只测外部可观察行为（HTTP 状态、响应体、写入前后数据库状态、响应头、cookie），不测是否调用了某个函数。登出重放的结论以实际行为为准，不以 `getUser()` 被调用作为通过依据（ADR 0013）。
- 测试分层（ADR 0009/0012）：pgTAP 在本地栈直接验证数据库函数与 RLS 策略（两主体、伪造 owner、重复提交、跨 owner 引用），随每次 CI 自动运行；经服务端的两令牌端到端测试验证接口契约与跨主体隔离。pgTAP 只证明策略本身，跨主体隔离仍以两个真实用户令牌的端到端测试证明；数据库层不得使用绕过 RLS 的管理身份代替被测合成主体。
- 续期必须走真实刷新路径（控制令牌有效期或真实到期），不得只 mock 刷新函数后声称通过；登出重放须用登出前复制的完整 cookie 在独立客户端分别请求读与写接口。
- 环境护栏测试使用隔离合成目标演示误配（URL 错、期望 ref 未改、二者一起错、sentinel 缺失、模拟 `user` 目标），核对检查目标数据没有改变，不能仅凭报错认定安全。
- 每个层面必须有独立证据：应用、RLS/外键、环境护栏、托管验证缺一项，不得用其他层通过替代。
- 代码级先例：本仓库当前尚无产品代码与测试（阶段 1 实现未启动），测试形态以 Issue #1 与 ADR 0013 的验收表为准；仓库内可参考的只有 v1 的设计契约测试与视觉验收脚本的复用约定（ADR 0014），其断言方式须按 v2 重建，不直接搬用。

## Out of Scope

- 完整聊天实现：上下文组装、模型调用、流式事件协议、停止与失败处理、Provider 接入与 fallback（ADR 0003/0004/0005/0006/0008）。
- 消息排队、接收/展示/执行顺序协调、首次可见事件定义（session.md 已记录为未决定）。
- canonical 数据模型的物理表结构、字段、索引与消息正文存法；attempt 与输入快照拆表与否。
- Provider 选择与 API key 核实、外部观测平台接入。
- 备份系统的设计与运维（ADR 0001 的自建每日备份属另一条线；本文只保留其特权凭据边界约束）。
- 找回密码、自助注册、多人账号、SMTP 与邮件链路。
- 单条删除的产品入口与历史导航交互（归属与删除语义在本文固定，交互属聊天实现）。
- 创建 Issue、云资源、连接用户库、部署；本轮 Git/PR 操作仅交付文档。
- 任何"已验证通过"的结论：本文所有验收条目当前状态均为未运行。
