# 接续与学习记录

## 阶段结构与计划

每阶段统一使用 `docs/plans/stages/stage-N/`：

| 文件 | 唯一职责 |
| --- | --- |
| `README.md` | 阶段入口、产物导航 |
| `plan.md` | 完整模块清单、依赖、调研决策及学习计划、覆盖状态 |
| `session.md` | 全局当前焦点、模块进度摘要、跨模块阻塞、授权、下一步与交接 |
| `spec.md` | 阶段总 SPEC 的 Issue 链接与发布状态，不复制正文 |
| `features/<slug>/` | 按需保存模块细节、局部接续和专项证据 |
| `evidence/` | 按需保存跨模块证据 |

入口、总计划、总接续从启动建立；SPEC 入口随规格产物建立，其余目录按需。恢复时缺总记录，按 [focus.md](focus.md) 补建。保留旧历史，安全迁移时更新指针，不伪造过去已完成的计划。计划中的模块即 feature，技术模块也可纳入清单，不强制一模块一目录或一子 SPEC。

总计划先明确阶段体验目标、范围、非目标及整体验收，再以稳定模块标识登记：

| 模块 | 要求来源与目标 | 依赖 | 调研与决策点 | 学习目标与活动 | 验收及证据 | 状态与材料链接 |
| --- | --- | --- | --- | --- | --- | --- |

覆盖每项阶段要求，标明共享契约归属；未开始的模块也列入。学习目标写学后能解释或判断什么，安排必要讲解、演示、理解观察与回访。确认与变更规则见 [focus.md](focus.md)。总计划组织已有权威要求，以来源链接追溯，不另立需求真源。

分别标注设计讨论、SPEC 确认/发布、文档合入、实现验收状态；学习另记已讲、理解证据及回访。模块收口不升级阶段状态，文档存在、标签或讲解完成不代表通过。

## 两层接续

阶段 `session.md` 必有；模块跨会话、有较多未决项或独立委派时，按需建立 `features/<slug>/session.md`。小模块只记阶段接续。主 Agent 串行维护总记录，worker 写独立证据。

阶段接续保留以下摘要，详情链接到总计划、ADR 或模块记录：

- 更新时间与来源、本次目标、当前模块和具体下一动作。
- 授权来源及边界、模块进度、阶段剩余范围、跨模块决定与阻塞。
- 活跃委派标识、结果路径、接续方式；文档冲突、易变证据、并行改动。
- 笔记与理解回访、待同步摘要及目标路径。
- 总/子 SPEC 状态与链接、未决/待验证项、PR 与合入回执、构建先读什么及先做什么。

局部接续顶部是 [focus.md](focus.md) 的状态卡和议题清单，其后保存模块内部证据与历史链接，不复制全阶段计划；总接续仅摘要并链接局部细节。模块切换和会话收尾同步总进度。恢复按总计划、总接续、当前局部接续读取，不遍历所有模块历史。

## 学习笔记

目录以 `CONTEXT.md` 为准，当前为 `/Users/lukemyself/Documents/学习/AI/Agent Harness`。写前核对 `study-notebook` 链接目标和已有分类，只读相关主题与理解记录；内容不进产品仓库。

复用已有结构，空目录按需创建：

- `topics/<topic>.md`：机制、适用条件、取舍、案例、来源。
- `learning-records/<date>-<session-id>-<topic>.md`：目标、实际理解表现、缺口、回访。
- `index.md`：主题与阶段链接，阶段末整理。

记录阶段、日期、关联提交及是否合入；无实现则标设计讨论、尚无代码，不以 HEAD 暗示落地。仅摘要必要技术讨论，不复制全聊天或私人内容。区分已讲、具体理解表现、需提示、未确认，不自动标掌握。

并行会话用独立标识写记录。更新共享主题与索引前核对其他写入者，由主 Agent 串行整合；无法协调则保留独立记录并标待整理。

符号链接不扩大写权限。权限不足走正常授权机制；仍不可写则在接续文件记待同步摘要与目标路径，恢复后核对同步。不得伪称已同步或把产品仓库作为永久笔记目录。
