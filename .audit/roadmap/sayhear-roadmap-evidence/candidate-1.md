# SayHear v2 阶段搭建与学习路线候选 1

研究基准日为 2026-10-20。本文件是独立研究候选，不是已接受的选型或实现授权。研究只读取项目与旧素材，没有修改仓库。没有创建 schema、逐 PR 计划或平台资源。

## 结论与状态

已定。以当前 `/Users/lukemyself/Projects/SayHear-v2/CONTEXT.md` 为准。年底交付能日常使用的文本 Agent，理解基础 Harness、canonical 数据、人格、基础记忆、Reflection、运行详情与验证。Web 部署到 Vercel。复用旧 Portal 的聊天交互。真实库与测试库隔离。初期数据归属兼容未来多用户。完整多用户、实时语音、日记、完整纠正与遗忘、Open Loop 后续推进。技术栈尚未决定。`docs/decisions.md` 当前没有 ADR。

推荐。把产品数据与来源规则掌握在应用中，把模型调用、流式协议、工具循环和后台可靠执行尽量交给成熟组件。先比较 AI SDK 与 Mastra 的实际适配成本，再锁定一条主线。默认倾向 AI SDK 作为文本产品调用与流式交互基础，采用其已有循环能力；Mastra 是有竞争力的替代，不因“框架太重”提前排除。推荐理由是年底需要看清每轮输入和自己的数据，尚无复杂图编排需求。这是项目适配判断，不能从官方能力文档推导出某框架产品效果更好。[H1][H2][H4][H5]

推荐。先形成一个托管 Postgres 的 canonical 数据来源，基础记忆先使用带来源的少量派生内容与可解释检索。Mem0 作为首个外部记忆候选；仅在它能减少真实工作量且通过来源、时间变化与隔离检查时采用。Graphiti 或 Letta 需要更明确的关系查询或状态管理收益。这里没有预设必须自建记忆引擎，也没有承诺只靠向量检索。[M1][M2][M3][M4]

待讨论。Luke 对人格的具体感受、首选 Provider、可接受的响应等待、数据区域与预算、公开用户范围，需要在对应阶段前确认。当前文件不改变 `CONTEXT.md` 的承诺。

待实测。Provider 的“兼容协议”是否覆盖流式工具调用、取消、结构化输出与错误信息；框架是否能交出完整运行输入；记忆在真实中文跨日对话中是否有用；Reflection 是否引入固化标签。SDK 提供接口不等于每个 Provider 支持全部特性，官方 AI SDK 能力表也明确存在差异。[H2]

## 先分平台层级，再选择组件

| 层级 | SayHear 需要保留的职责 | 可采用的组件 | 能力限制 |
| --- | --- | --- | --- |
| 模型与 Provider | 选择发出的内容，记录能力与错误差异 | 模型 API、AI SDK Provider、服务商网关 | API 格式兼容不能证明工具与流式行为一致。[H2] |
| 对话调用与 Agent 运行 | 上下文策略、人格、工具准入与停止预算 | AI SDK、Mastra、LangGraph、OpenAI Agents SDK、Claude Agent SDK | 这些候选覆盖范围不同；框架的 session 或 memory 不自动成为产品 canonical 数据。[H1][H3][H4][H6][H7] |
| 产品记忆 | 自述与推断的区分、依据、时间变化、使用规则 | Mem0、Graphiti、Letta，或应用内轻量派生与检索 | 存储或检索记忆不等于正确理解，仍需应用评测。[M1][M2][M3][M4] |
| 持久化与访问 | 用户归属、原始记录、派生产物关联、真实与测试隔离 | Supabase 或 Neon 的 Postgres | 托管数据库不自动配置正确的租户隔离，也不定义删除派生内容的产品语义。[D1][D2] |
| 后台可靠执行 | Reflection 处理范围、失败可见、重复执行安全 | Inngest、Trigger.dev，简单情况可用 Cron 加可恢复处理 | 调度、执行恢复和数据库事务是不同职责；重试不能证明外部副作用恰好一次。[B1][B2][B3] |
| 可观测与评测 | 用户能展开的运行详情、合成数据、评判标准 | Langfuse 或 Braintrust，应用内运行详情 | 第三方追踪不应成为私人内容的默认外送通道；自动评分需要人工校准。[O1][O2][O3] |
| Web 部署 | 在线聊天、登录与访问边界、错误恢复 | Vercel 与复用的 Portal UI | Web 部署不能直接证明任意持久 Agent 进程可按同样方式运行。[H7][B3] |

不建议同时安装多个 Agent 框架、两个记忆服务、多个评测平台。不同层可以组合，同层只保留一个主实现。每个新增服务都需说明它替代了哪些工作，以及引入了哪些状态与运维责任。这是对约 100 小时学习预算的取舍。

## Harness 候选及拒绝理由

| 候选 | 官方可核实能力 | 对 SayHear 的收益与成本判断 | 年底处理 |
| --- | --- | --- | --- |

| LangGraph | 面向长时、有状态 Agent 的低层编排，提供持久化、人工介入及长期状态机制。持久恢复需配置持久 checkpointer，内存保存不能跨进程重启。[H3] | 适合复杂分支、暂停恢复、状态图。本阶段核心路径简单，图状态与产品数据的关系需要额外学习。 | 暂不采用。未来真正需要跨步骤暂停、人工审核或复杂可恢复控制流时重评。不是能力不足。 |
| OpenAI Agents SDK | TypeScript SDK 提供工具、handoff、guardrail、session、streaming 和 tracing。支持 AI SDK 模型适配器及自定义 ModelProvider。[H6] | 不应误称仅支持 OpenAI。适合需要这些 Agent 机制的产品；当前尚无 handoff 需求，采用后仍要核验非 OpenAI Provider 及追踪数据路径。 | 备选，不与 AI SDK 叠加作默认架构。Provider 适配不是拒绝理由，额外运行抽象是否产生收益才是。 |
| Claude Agent SDK | 在自营进程中运行 Claude Code binary，提供工具、权限、session、hooks、MCP、subagent，支持 Python 与 TypeScript。Client SDK 与 Managed Agents 是另外两种接入层级。[H7] | 完整任务 Agent 的现成行为有价值，但文件与命令工具不是本阶段陪伴的主要需求。需要明确运行环境和权限边界，不能把运行 Claude Code 的进程当作普通无状态聊天函数。 | 不作本阶段默认。未来引入受控工作空间任务再评估。拒绝理由是运行及产品适配，不是模型质量。 |
| 按需轻量循环 | AI SDK 文档提供手动循环方式，开发者可自行管理模型、工具结果与步骤。[H1] | 最易逐行理解，也要自己承担停止、重复调用、流式状态和失败组合。只有现成循环确实阻挡必要行为才有理由增加此责任。 | 不把手写循环当学习毕业要求。可用讲解或小型沙盒说明机制，不先建生产框架。 |

选型验证总共控制在 Luke 约 6 小时以内，计入阶段一。Agent 可后台完成资料与接线。只对 AI SDK 和 Mastra 使用相同合成对话、同一 Provider、同样的一个只读工具与相同上下文规则。检查流式、停止、失败、可展开输入、历史恢复和派生来源。其他框架已有文档足以解释本阶段不优先，无需各写一套。

选择依据是完成核心用户路径需要的适配工作、能否解释状态归属，以及是否存在阻断项。不编造统一评分权重。两者均满足时采用更少重复状态的一方。若 Mastra 自带能力明显降低后续 Reflection 与记忆工作的适配量，优先 Mastra；若必须绕过其 memory 与存储才能保住来源和输入控制，优先 AI SDK。这是待实测的选择门槛，不是预先宣判。

## 记忆、数据库、任务与评测的组合判断

### 记忆不等于长期存储

原始消息用于保留用户实际表达，派生记忆用于选择之后值得带入的信息，Reflection 用于有依据地形成观察。三者职责来自共识，不预设为三张表。记忆模块必须能说明输入范围、产物来源、何时生效与检索结果，不能把用户说过的话自动当外部事实。

| 方案 | 能力与限制 | 采用条件与拒绝理由 |
| --- | --- | --- |
| Mem0 | OSS 提供可配置模型、embedding 与存储接入。官方区分 OSS 和 hosted Platform 的历史处理及异步行为。`user_id` 等标识用于作用域，文档描述不等于完整鉴权保证。[M1][M2] | 最接近可插入的记忆组件。待实测来源映射、时间变化、中文及删除行为。默认存储与模型不是产品决定；不能原样采用默认配置处理私人数据。 |
| Zep 与 Graphiti | Graphiti 是开源时序知识图谱，按 episode 增量抽取，结合语义、全文与图检索，关系可随时间失效。Zep 是使用 Graphiti 的托管上下文产品，两者不是同一种采购方案。[M3] | 若多人物关系与时间查询成为主要瓶颈再采用。现在增设图数据库、图提取和回收维护，收益未证实。时序机制存在不等于抽取的日期与人物必然正确。 |
| Letta | 状态化 Agent 持久保存消息与工具调用。memory blocks 在上下文中，archival memory 按语义检索，conversation search 搜过去消息。Agent 与开发者均可管理部分记忆。[M4] | 若希望连运行状态与记忆管理一起复用，可作为整体方案。当前不把它视为纯数据库插件；与另一框架双重管理 session 会增加理解负担。 |
| 应用内少量派生与检索 | 推荐方案本身，不是现成产品能力声明。用当前有限历史、来源可追踪的派生内容和按需检索形成基线。 | 适合先理解与验收，限制是应用要承担提取和检索规则。若 Mem0 通过同样验收且减少工作量，就采用 Mem0；不要为自建投入找保留理由。 |

不以 LoCoMo 排名或厂商延迟宣传定案。本候选未重跑基准，也不引用旧资料中的不可比数字。短历史时保留完整相关对话作为评测对照很有用，但不把“全部历史永远塞入模型”作为产品策略。这个判断是设计建议。

推荐在阶段四只验证一个外部候选 Mem0。用相同来源材料与问题，对比应用基线，最多一个有明确终点的验证周期。优先检查错误记忆与无依据推断，再看召回。若它无法稳定交出来源或使产品语义受限，就停止集成，保留研究结果。

### 数据库服务

Supabase 每个项目提供 Postgres，数据库扩展包括 pgvector，Auth 与数据库结合，RLS 可保护客户端访问。官方说明数据库备份不包含 Storage API 中的对象。[D1] Neon 官方介绍提供托管 Postgres、branching、autoscaling、scale to zero 与 restore。[D2] 这些能力都不能替代自己验证访问控制与恢复。

推荐以 Supabase 为优先讨论候选，因为初期真实在线聊天需要基本访问控制，未来也要多用户。若 Luke 更愿意独立组合鉴权并重视数据库分支工作流，Neon 同样合理。该选择不依据未核实的免费额度或价格。先核验所在区域、连接池、扩展、备份与恢复能力及当前套餐，然后决定。

已定的测试库与用户库应采用真正隔离的数据库与凭证，不把“同一库里多一个环境字段”视为满足共识。Branch 是开发便利功能，不自动满足隐私隔离；不得从真实用户库复制私人记录到测试环境。需要可重复装载的合成数据与明确的环境识别。这里只定义验收边界，不提前设计 schema。

### 后台任务

Reflection 初期推荐手动触发并可回看，先验证产物，再决定自动节奏。自动化后仍需在线服务独立于 Luke 的电脑，这是共识要求。

Inngest 通过 named steps 保存结果，失败步骤可重试，handler 恢复时会重放并使用已保存结果。官方明确外部副作用可能已发生而结果未成功保存，应用仍需保证重复执行安全。[B1] Trigger.dev 提供长任务、等待恢复与可配置重试，需自己的任务运行部署配置；其任务概览没有替应用保证数据写入恰好一次。[B2] Vercel Cron 是定时触发函数，官方明确失败不自动重试、可能重复或漏掉触发，并受函数执行时长限制。[B3]

推荐在“Reflection 自动运行且需要跨失败恢复”时选择 Inngest 或 Trigger.dev 之一。若仍只有短小、可补跑的每日批处理，Cron 加任务记录和补偿扫描也可接受。拒绝“发出请求后无记录地后台继续”，因为很难确认哪些历史已处理。不要为了未来 Open Loop 提前搭复杂任务平台。任务平台负责可靠执行，Reflection 的质量与更新准入仍归产品。

### 可观测与评测

推荐应用内保留用户可展开的运行详情，包括实际送给模型的输入、历史选择、记忆结果、工具与失败位置。追踪平台提供开发与实验能力，不能代替该产品需求。

Langfuse 文档覆盖 OpenTelemetry 追踪、数据集与实验、代码评分、LLM judge、人工标注和反馈。[O1] 其应用侧 masking 可在导出前处理数据，其他 exporter 的副本不会因此自动被处理，collector masking 则发生在离开应用之后。[O2] Braintrust 文档覆盖数据集、scorer、实验和异步生产评分。[O3] 二者都不能证明 judge 分数等于“被理解”的体验。

推荐先选 Langfuse 或仅使用最小本地实验记录，避免一开始自托管完整观测栈。云平台只接收合成数据，真实会话默认只输出必要元数据；任何内容级导出需在数据边界决策时说明。自托管也有维护、访问与备份成本。对私人对话的在线质量判断可由 Luke 自愿选择片段，不能自动变测试集。

人格的阶段评测建议围绕具体场景。用户抱怨工作时先理解而非立即给计划。面对有害或片面的自我评价，温暖地保持判断。用户表达不想继续时停止追问。隔日提起过去内容时既保留连续性，也允许用户已经改变。没有证据时表达不确定。以上是由当前共识推导的推荐验收，不是产品竞品已经证明的最佳参数。

完整日记、对话外主动消息、浪漫角色系统都不进入年底范围。当前没有必要把长期愿景所有能力均做一个入口。

## 十周路线及阶段 feature spec

总量按 Luke 约 100 小时规划，包含阅读、讨论、讲解、体验和笔记。Agent 后台工作不计入。以下小时是协作预算估计，不是实测开发工时，也不是交付保证。2026-10-20 至 12-31 多于整十周，按十个工作周计划，12-29 至 12-31 保留日历缓冲，不额外承诺 Luke 的投入。

| 阶段 | 周与预算 | 用户能感知的结果 | 阶段结束所需证据 |
| --- | --- | --- | --- |
| 0，路径与边界共识 | 第 1 周，10 小时 | 明白接下来要做成什么，选定一条运行主线 | 一次可检查的候选比较、数据发送边界、优先 Provider 与退路 |
| 1，真实文本对话与 canonical 数据 | 第 2 至 3 周，22 小时 | 在线打开聊天，流式交流，重开页面保留历史，失败可理解 | 真实部署演示、隔离检查、单轮输入与保存结果可追踪 |
| 2，人格与上下文 | 第 4 至 5 周，18 小时 | 对话自然、有立场，长一点的对话仍知道在谈什么 | 相同场景的回复比较、上下文选择记录、Luke 对行为的解释 |
| 3，跨日基础记忆 | 第 6 至 7 周，22 小时 | 隔日不必重讲重要背景，并能知道记忆来源 | 时间变化与人物混淆数据集、记忆开关对照、来源检查 |
| 4，Reflection 与运行可靠性 | 第 8 至 9 周，18 小时 | 逐步理解用户且能回看依据，后台失败可恢复 | Reflection 前后对照、重复执行演示、错误产物回看 |
| 5，日用验收与知识整合 | 第 10 周，10 小时 | 稳定日常文本使用，知道限制与下一步 | 日用反馈、回归结果、Luke 跨层定位一次真实问题 |

第 1 周从 10-20 开始，第 10 周为 12-22 至 12-28。阶段用相对完整机制划分，周数允许平移。每周检查完成结果、Luke 实际投入与未解决问题，不以提交数或学习笔记字数判断进度。

### 阶段 0 的 feature spec

目标是把复用与自有边界讲清楚。范围包括核实旧 UI 可复用程度、首个 Provider 的真实服务与协议、AI SDK 和 Mastra 的有限适配比较、数据库区域与环境策略。暂不设计最终消息模型，也不搭全部平台。

验收要求是同一个合成场景可以说明输入、模型、工具、停止与输出各由谁负责。候选具有明确退出条件。关键选型获得 Luke 共识，落地时再形成 ADR。若六小时比较仍无明显差异，选择满足需求且重复状态较少的一方，停止横评。

学习证据是 Luke 沿一次调用解释模型 API、SDK、Agent runtime、memory、数据库与任务服务的不同职责，并能说出为什么没有同时采用多个运行框架。待确认项是 Provider 的具体名称与协议、付费预算和数据区域。

### 阶段 1 的 feature spec

目标是在线随时进行可靠文本交流。范围包括复用聊天 UI、流式输出、停止与失败反馈、历史保存、原始输入与生成产物的来源关联、实际模型输入查看、基本访问控制与合成测试库。此处只提出语义要求，数据形状在阶段开始后共同决定。

验收要求是页面刷新后历史仍在；流中断或取消有可解释状态，不能假装完整成功；工具循环存在明确结束预算；同一请求重复到达不生成混乱历史；Provider 失败能定位；测试凭证不能操作用户库；用两个合成用户验证数据不能串读。兼容未来多用户不等于本阶段交付完整账号管理。

学习证据是 Luke 从浏览器消息跟到服务端输入、模型流与数据库结果，解释为什么 UI 消息、API 消息和原始用户表达不宜直接混为一谈。待确认项是取消后保留哪些可见内容，以及初期登录体验。

### 阶段 2 的 feature spec

目标是先让“被听懂”成立。范围包括稳定人格、上下文选择与长度预算、历史截取或摘要的依据、基础工具调用与停止、运行详情可展开。不会为了显示 Agent 能力增加外部搜索或多 Agent。

验收使用一小组高信息量合成对话，建议初始约 12 个场景，只是覆盖预算。覆盖不急于建议、不过度附和、尊重停止、非人类身份诚实、长对话主题保持、工具结果中的不可信指令、Provider 特性缺失。客观规则用程序检查，温暖与判断用 Luke 和 Agent 对照讨论。关键边界失败应修复，不能被平均分掩盖。

学习证据是 Luke 查看实际输入后解释某条历史为何留下或被排除，能区分人格问题、上下文遗漏和 Provider 行为差异。待确认项是两三个 Luke 感觉合适与不合适的回复例子，不能只用“更有灵魂”作验收。

### 阶段 3 的 feature spec

目标是形成可信的跨日连续性。范围包括有来源的记忆派生、检索、时间变化、无相关信息时不强行召回、记忆查看与基本清理。完整自然语言纠错、联动遗忘及日记重建留后续；日用前仍必须能查看内容并清理私人数据，这是共识底线。

验收建议采用约 20 个经过人工确认的跨日场景，覆盖同名人物、转述他人、用户偏好变化、否定、时间相对表达、AI 推断、不相关私密细节、未知答案与恶意历史指令。每个用例记录应出现和不应出现的依据。对照相同上下文预算下开启与关闭记忆的行为；不以系统存了多少条证明有效。无依据断言、跨用户泄漏和把旧偏好说成当前确定事实作为阻断问题。20 是初始维护预算，不代表统计显著或总体可靠性。

外部记忆候选仅验证 Mem0 一次，比较同一批场景与来源可见性。若收益不明确，不继续并行验证所有厂商。学习证据是 Luke 能沿“原话、派生、检索、注入、回答”定位一条错记来自哪一步，说明为何用户自述与 AI 观察不能混写。待确认项是哪些敏感信息进入长期记忆，以及哪些召回会让 Luke 感到被监视。

### 阶段 4 的 feature spec

目标是逐步理解变化，保持推断可修正。范围先手动 Reflection，输入是明确的一段历史，产物保留依据与处理范围。只有通过对照后才接自动任务，画像更新不是永久给人贴标签。

验收要求是用户说过的经历、意见与 AI 推断能区分；旧画像不覆盖原始表达；新的矛盾表达能触发重新判断；不强行推断心理诊断；无新内容时不重复制造结论；Reflection 失败后可补跑；相同工作重复触发不会产生重复生效的产物。下一次对话展示它究竟改变了哪些输入与回答。客观可靠性与主观理解收益分开记录。

学习证据是 Luke 解释为什么整理放到后台、任务重试为何仍需处理重复写入、为什么一篇措辞漂亮的 Reflection 不等于理解正确。待确认项是触发节奏、画像中哪些观察能默认用于之后对话，以及是否采用任务平台。

### 阶段 5 的 feature spec

目标是稳定日用并整合知识，不再新增大功能。范围包括部署与恢复检查、已知失败回归、数据查看清理、Provider 切换演练、运行详情整理和阶段回顾。

验收要求是 Luke 能连续使用数天并指出可用与不可信之处；通过一次合成故障定位与恢复；关键数据隔离与来源检查保持通过；清楚列出仍未覆盖的纠错、遗忘、日记与多用户能力。数天日用是体验信号，不是长期稳定性证明。

学习证据是 Luke 在 Agent 少量提示下解释完整链路，针对一次真实错误选择该查哪层，并在隔几天后的新场景中仍能迁移这个判断。待确认项是哪些限制阻碍日用，以及下一阶段先做纠正遗忘、日记还是语音。

## 学习方法与时间分配

推荐每阶段采用一次完整机制的示范，再由 Luke 沿真实运行解释因果，然后对一个小变化作判断，最后隔几天在新场景重新讨论。Agent 可承担样板代码与后台调查，Luke 重点参与关键决策、观察与解释。初期给更多引导，理解稳定后再减少提示。不安排为了教学而故意制造无意义的失败。

Dunlosky 等人的综述将 distributed practice 与 practice testing 评为高效用方法，自我解释为中等效用；证据跨学习材料与条件，但不直接证明独立开发者能靠本路线掌握 Agent 工程。[L1][L2] 在这里采用间隔重访与无评分的实际解释，不安排考试、背诵题或课程时长指标。笔记用于恢复上下文和保留问题，不能单独作为掌握证据。

每周 10 小时可参考分为真实产品体验与讨论 3 小时、沿代码与运行讲解 3 小时、阅读与关键判断 2 小时、回顾与笔记 1 小时、机动 1 小时。这是建议分配，碎片化参与可调整。正常使用的反馈必须安排在预算内，不把学习放成开发完成后的额外任务。

理解证据按持续状态记录为“需引导解释”“可独立解释”“能在新场景应用”，不按一次回答盖章。例子包括解释取消如何影响持久化、分辨错误发生在检索还是生成、判断某个推断能否进入画像。隔一阶段再碰相同机制，确认其仍能用于判断。这里的状态是协作记录，不是考试成绩。

## 延误时的取舍与停止条件

约 100 小时不足以同时做复杂框架横评、生产多用户、图记忆、完整纠错遗忘、日记、主动通知与语音。保留能日用的文本对话、数据边界、来源、人设、基础记忆和一次有依据的 Reflection 主线。

若进度紧张，先减少界面装饰、外部观测平台集成、第二 Provider 的深度支持、自动 Reflection 频率和非关键工具。第二 Provider 至少要说明接入边界并完成有限替换验证，不能把“可替换”只写在文档里。Reflection 可降低为手动触发但保持在线可运行与可补跑。若这影响当前共识的交付承诺，需要明确与 Luke 调整。

不削减测试与用户数据隔离、基本访问控制、原始表达保留、无依据内容的区分、失败可见和基本清理。阶段 1 没有可靠记录就不抢先做 memory；基础记忆未通过来源检查就不扩大画像；Reflection 无明确收益就不因调度方便自动运行。

第 3 周仍无法在线稳定对话时冻结平台扩展。第 7 周记忆仍频繁混淆来源时，缩小记忆写入范围，优先保留用户明确表达与可回看来源，再讨论范围。第 9 周只收敛已有能力。所有时间点是管理建议，不是已接受的项目门槛。

## 待共同确认的最少事项

1. 本路线是否继续保持年底六个阶段目标。若总投入下降，哪些体验最需要保留。
2. 首个真实 Provider 的服务、协议和数据条款，以及可接受的数据区域、预算与保留范围。API key 留在环境管理，不进入研究材料。
3. AI SDK 与 Mastra 的选择标准是否认同，哪种重复状态或适配成本足以改变选择。
4. 初期访问对象是否仅 Luke。对外用户需要额外明确年龄、危机响应、隐私与清理边界，不在本研究里默认完成。
5. 哪些跨日例子最能代表“被记住”，哪些推断或召回令人不舒服。
6. Reflection 的默认可用范围和最低用户控制。完整遗忘后移不等于允许基本内容无法清理。

这些问题无需阻断当前研究。实现前按阶段讨论，并把真正达成的决定写入项目权威位置。

## 来源与能力限制

以下 URL 在本次研究中通过页面抓取或搜索核对。未写版本号、发布日期和价格承诺。官方页面会变化，进入实施阶段还需核对实际安装版本与所选套餐。抓取不完整的页面明确标注。

- [H1] AI SDK，https://ai-sdk.dev/docs/introduction 与 https://ai-sdk.dev/docs/agents/loop-control 。文档支持调用、UI 与循环控制机制，不支持陪伴质量、持久执行或全部 Provider 的同等兼容保证。循环默认值不作为本路线的产品预算。
- [H2] AI SDK Provider 能力表，https://ai-sdk.dev/providers/ai-sdk-providers 。不同 Provider 与模型的 object generation、tool use、tool streaming 能力存在差异，表格也非穷尽列表，具体服务仍需实测。
- [H3] LangGraph 概览与 durable execution，https://docs.langchain.com/oss/javascript/langgraph/overview 与 https://docs.langchain.com/oss/javascript/langgraph/durable-execution 。支持状态编排与持久化设计；持久 checkpointer 需配置，LangSmith 的观测与部署属于额外服务。不能自动保证业务副作用正确。
- [H4] Mastra Agent 概览，https://mastra.ai/docs/agents/overview 。支持工具、生成、流式、结构化响应及工作流组合；官方概览不构成性能或部署可靠性保证。
- [H5] Mastra memory，https://mastra.ai/docs/memory/overview 。说明 resource、thread、历史、semantic recall 与 working memory 及存储要求。资源作用域配置不是应用鉴权，也没有证明自动归纳正确。
- [H6] OpenAI Agents SDK，https://openai.github.io/openai-agents-js/ 与 https://openai.github.io/openai-agents-js/guides/models/ 。主页抓取含大量导航，模型页正文从官方搜索结果核对，支持 AI SDK adapter 与 custom ModelProvider。对某个第三方服务的全部兼容性不能据此保证。Python 机制不自动推定 TypeScript 完全等价。
- [H7] Claude Agent SDK，https://code.claude.com/docs/en/agent-sdk/overview 。明确运行 Claude Code binary、自营进程、内建工具及 Python 与 TypeScript。Client SDK 和 Managed Agents 为不同接入层。SDK 不免除应用的数据与权限责任，产品认证也不能默认借用 claude.ai 登录权益。
- [M1] Mem0 OSS，https://docs.mem0.ai/open-source/overview 。模型、embedding 和存储可配置；默认值不构成项目推荐。该页未给来源语义或效果保证。
- [M2] Mem0 memory operations，https://docs.mem0.ai/core-concepts/memory-operations 。可核对新增、检索作用域及 Platform 的异步处理。不同模式存在行为区别，该页不足以证明全部历史、删除和权限语义。
- [M3] Graphiti，https://help.getzep.com/graphiti/getting-started/overview 。支持 episode、时序关系与混合检索，并区分 OSS Graphiti 与 Zep 托管方案。图结构不能保证抽取正确，也不能消除数据治理工作。
- [M4] Letta，https://docs.letta.com/guides/agents/memory/ 与 https://docs.letta.com/guides/agents/archival-memory/ 。memory blocks、archival memory、消息搜索及状态持久化有不同职责。长期可存储不等于可准确回忆，具体保留政策与部署需另核。
- [D1] Supabase database，https://supabase.com/docs/guides/database/overview 。Postgres、扩展、RLS、Auth 和备份有官方说明，数据库备份不包含 Storage 对象。具体区域、恢复及套餐限制未在本研究锁定。
- [D2] Neon，https://neon.com/docs/introduction 。托管 Postgres、branching、autoscaling 与 restore 的官方入口。本次返回内容包含更广产品介绍，不据此假设所有服务与地区均可用；连接与套餐限制需按所选方案重核。
- [B1] Inngest functions，https://www.inngest.com/docs/learn/inngest-functions 。保存步骤结果与重放支持恢复，明确存在外部副作用完成而步骤结果未保存的窗口。
- [B2] Trigger.dev tasks，https://trigger.dev/docs/tasks/overview 。长任务、等待、重试与可配置时限有文档支持。不是无限资源承诺，也未替应用提供数据库事务一致性。
- [B3] Vercel Cron，https://vercel.com/docs/cron-jobs/manage-cron-jobs 。失败不自动重试，调度可漏发或重复，可能并发，受函数时限约束。套餐调度精度应在实施时复核。
- [O1] Langfuse，https://langfuse.com/docs 。追踪、数据集、实验与多种评测机制有官方说明。自托管能力不表示维护成本低，自动评分不等于体验事实。
- [O2] Langfuse masking，https://langfuse.com/docs/observability/features/masking 。说明应用侧与 collector 侧脱敏的边界及多个 exporter 的限制。
- [O3] Braintrust evaluation，https://www.braintrust.dev/docs/evaluate 。数据集、scorer、实验与生产异步评分的官方流程。未据此断言成本、评分准确率或隐私保证。
- [P1] Tolan 的 OpenAI 官方案例，https://openai.com/index/tolan/ 。本次正文抓取 403，官方搜索摘要核对了上下文重建与检索描述。属于供应商案例中的团队自述，不作独立效果与因果证据。
- [P2] Character.AI memory，https://blog.character.ai/memory/ 。可核对 memory 控制界面及套餐差异；“记得更好”属于产品声明，页面未提供独立验证。
- [P3] Rosebud，https://www.rosebud.app/ 。用于核对官网宣称的日记、记忆、模式回顾与周报。不是心理疗效证据，静态及传输加密也不是 E2EE。
- [P4] Day One AI features，https://dayoneapp.com/guides/ai-features/ai-features/ 。明确 AI 内容的解密和发送过程及 opt-in；不将其训练或保留声明推定到其他 Provider。
- [P5] Day One privacy FAQ，https://dayoneapp.com/privacy-faqs/ 。说明日记加密与导出选项，不能从此推定 SayHear 可在服务端推理时提供同样的 E2EE 边界。
- [L1] Dunlosky 等，Improving Students' Learning With Effective Learning Techniques，https://doi.org/10.1177/1529100612453266 。学习方法综述，对 practice testing、distributed practice 和 self-explanation 的效用评价是一般证据，不能直接推导本项目学习效果。
- [L2] APS 对该综述的说明，https://www.psychologicalscience.org/publications/journals/pspi/learning-techniques.html 。支持间隔实践与实际提取的方向，页面摘要不足以说明所有机制及应用条件。

本候选应用了 Experience First 原则，把有限时间集中在被理解、被记住与可解释的日用体验，后移图记忆与日记。应用了 Prove It Works 原则，为阶段交付同时要求真实行为、体验和理解证据；当前研究不把建议验证描述成已完成实测。写作按本次读取的 unslop 与 technical-writing 指引区分事实、建议和证据限制。
